# 『つなぐ×ならべる』クオリティアップ 第3部: 仕上げ 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 次の流れを、商用ゲームの手触りにする。
- 画面の流れ: 読み込み → タイトル → モード選択 → キャラ選択 → VS 演出 → 対戦 → 結果
- あわせて: 設定画面（音量・演出の強さ・揺れや点滅を抑える）、チュートリアル、戦績、紹介画像

**Architecture:**
- 画面はいまと同じ「HTML のオーバーレイ」で作る。画面ごとの中身を組み立てる処理は `ui.js` に分け、`app.js` はゲームループと画面の切り替えだけにする。
- ロジックは純粋な関数にして Node でテストする。
  - `records.js`: 戦績の集計
  - `tutorial.js`: 課題の盤面と、できたかの判定
- ゲームの中身（盤・試合・CPU）には触らない。

**Spec:** `docs/superpowers/specs/2026-10-10-tsunagu-naraberu-quality-up-design.md`（3章）

## Global Constraints
- 既存のテスト（101件）がすべて通ること。演出の有無で試合結果が変わらないこと
- 画面はすべて、キーボード（矢印＋決定/戻る）・ゲームパッド・タッチの3つで操作できる
- PC 1280×800 と 375×812 で、はみ出し・重なりなし
- 揺れや点滅を抑える設定のときは、画面の揺れ・点滅・カットインを出さない

## Review Focus
1. 読み込みに失敗した絵がある（回線が悪い）→ 読み込み画面で止まらず、その絵だけ描かずに進む
2. 戦績の保存が壊れている、または古い → 0から数え直す（例外を出さない）
3. チュートリアルの途中で盤が詰まる、または課題と関係ない操作をする → その課題を盤面ごとやり直せる。詰まっても先へ進まない
4. VS 演出やキャラ選択の最中に連打する → 二重に試合が始まらない
5. 音量0・演出「低」のまま遊ぶ → 音を鳴らす処理や演出の処理が例外を出さない

### Task 1: records.js（戦績）
- 保存先: `tn-records-v1`。中身は次のとおり
  - `{plays, cpu: {[level]: {win, lose}}, chars: {[id]: {win, lose, plays}}, bestChain, bestAttack}`
- `recordResult(rec, {mode, level, chars:[me, opp], result:'win'|'lose'|'draw', maxChain, attack})`
  - 返り値: `{newBestChain, newBestAttack}`
  - CPU戦: 段別とキャラ別の勝敗を数える
  - 2人対戦: 回数と1Pキャラの plays だけを数える
  - 練習・チュートリアル: 数えない
- テスト: 集計・自己ベスト更新・壊れた保存・未知の段

### Task 2: 音量と演出の設定を、音・描画・キャラにつなぐ
- `audio.setVolumes({bgm, se, voice})`: 0〜100。0なら鳴らさない
- 演出「低」または揺れを抑える設定のとき
  - render: 画面の揺れなし、消去の点滅を弱く、破片を半分に
  - chara: カットインなし
- 揺れを抑える設定の初期値は `matchMedia('(prefers-reduced-motion: reduce)')`

### Task 3: tutorial.js（あそびかた）
- `TUTORIALS = { tsunagu: [...], naraberu: [...] }`。各課題は `{title, text, setup(board), goal(board, events, ctx) → bool}`
- 課題
  - つなぐ派
    1. 左はしに置く
    2. 4つつなげて消す
    3. 2連鎖を組む
    4. おじゃまを巻き込んで消す
  - ならべる派
    1. 入れ替える
    2. 3つ並べる
    3. 2連鎖
    4. アクティブ連鎖（浮遊を長めにする）
    5. せり上げる
- テスト
  - 各課題が、始めた直後は未達である
  - 決めた手順の入力で達成できる（解けることの証明）

### Task 4: 画面（ui.js・HTML・CSS）
- **読み込み**: 立ち絵36枚の読み込み率を出す（失敗しても進む）
- **タイトル**: ロゴのアニメ、4人の立ち絵、「はじめる」（どのキーでも）
- **モード選択**: CPUと対戦／ふたりで対戦（PC）／れんしゅう／あそびかた／戦績／設定
- **キャラ選択**
  - 4人の大きなカード（select.webp）。選ぶと `select` の声
  - CPU戦: 相手のキャラ（おまかせあり）と CPU の強さ
  - 2人対戦: 2人が同時に選ぶ（1P は WASD、2P は矢印）
  - ハンデは「くわしく」に入れる
- **VS 演出**: 左右から立ち絵、VS、名前。約2秒。キー・タップで飛ばせる
- **結果**: 勝ったキャラの `win` 立ち絵と負けたキャラの `lose`、成績、自己ベスト更新の表示
  - ボタン: もう一回／キャラを選び直す／メニュー
- **設定**: 音量3つ（スライダー）、演出の強さ、揺れや点滅を抑える、操作の設定（既存）へ
- **戦績**: 遊んだ回数、CPU段別の勝率、キャラ別の勝率、最大連鎖、最大攻撃
- **共通**
  - 画面の切り替えは0.25秒のフェード
  - ボタンを押すと沈み込み、音が鳴る
  - フォーカス中のボタンを光らせる（キーボード・パッドで選べる）
