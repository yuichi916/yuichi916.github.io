# ひとり歓迎マップ フェーズ2B「情報の収集と再構成」設計

- 日付: 2026-08-08
- 状態: 設計中
- 前提: フェーズ2A（実装済み・公開済み）

## 1. 何をするのか

多数のサイトから**事実を集め、突き合わせ、自前の指標に作り直す**。引用はしない。

現在の3軸（ひとり度・静けさ・入りやすさ）は業態から機械的に推定した値である。「銭湯だから easy=3」のように、同じ業態なら全部同じ値になる。これを、実際に確認できた事実に基づく値へ置き換えていく。

置き換えの例。券売機がある店と番台で対面払いの店では、初めて入るときの心理的な負担が違う。今はどちらも `easy=3` だが、券売機の存在が複数の情報源で確認できれば `easy` を上げてよい。**この判断はうちがやる。どこかのサイトの点数を借りてくるのではない。**

## 2. 実測（設計の前に測った）

4施設で検索を実行し、許諾上問題のない情報源から何が取れるかを確かめた。

| 施設 | 性格 | 取れたもの |
|---|---|---|
| 竹瓦温泉 | 有名観光温泉 | 券売機あり（**5情報源**）、黙浴、休憩所の椅子、営業6:30-22:30、普通浴300円、砂湯は予約不可・整理券制・定員8名、電子マネー可 |
| 田の湯温泉 | 無名の市営銭湯 | **別府市公式サイト**で営業時間・料金・清掃時間・回数券。個人ブログ2件で番台あり（券売機ではない）、脱衣所4〜5人で一杯、ロッカーなし、地元客中心、定休日 第1火曜 |
| 別府中華そば 熊猫 | 開店4年の飲食店 | **大分経済新聞**で「カウンター6席、テーブル10席」、営業時間。ローカルメディアで定休日 |
| 薮庄 | 無名の蕎麦屋 | **ほぼ何も取れない。** 該当する結果は食べログ1件のみで、そこは自動アクセス禁止 |

### この測定から言えること

**カテゴリと来歴で当たり外れが大きく分かれる。**

- **温泉・銭湯は当たる。** 自治体が市営温泉のページを持ち、温泉巡りを趣味とする人のブログが厚い。無名でも当たる
- **飲食は、報道されたか地域メディアに載ったかで決まる。** 載っていれば席数まで分かる。載っていなければ食べログしか無く、そこは使えない
- **「1000サイトから全施設ぶん」は成立しない。** 37,193件すべてに当たりがあるわけではない

したがって本フェーズは**全件の網羅を目標にしない**。当たりの多いところから埋め、**どこを調べてどこを調べていないかを利用者に見せる**。

## 3. 使ってよい情報源・使わない情報源

**使わない（自動アクセスを禁止しているため）**

- 食べログ、サウナイキタイ、Retty

これは著作権の問題ではなく**アクセス規約の問題**である。検索結果に出てきても、事実の出所として数えない。コードでドメインを遮断する（運用の約束にしない）。

**使う**

- 自治体・公的機関の公式サイト
- 施設自身の公式サイト・公式SNS
- 地域経済新聞、ローカルメディア
- 個人ブログ、note、はてなブログ
- 温泉・銭湯の愛好者サイト

## 4. 何を集めるのか

**自由記述は集めない。** 決められた語彙の事実だけを集める。文章を保存しないので、他人の表現を持ち込むことがない。

| 事実 | 値 | 効く軸 |
|---|---|---|
| `payment_method` | `ticket_machine` / `counter_person` / `cashless_ok` / `cash_only` | 入りやすさ |
| `counter_seats` | 整数 | ひとり度 |
| `seats_total` | 整数 | — |
| `reservation` | `none` / `possible` / `required` | 入りやすさ |
| `silence` | `posted`（黙浴の掲示）/ `observed`（会話が少ないという記述） | 静けさ |
| `clientele` | `local`（地元客中心）/ `tourist` / `solo_common`（一人客が多い） | 入りやすさ・ひとり度 |
| `first_timer` | `easy` / `custom_exists`（作法がある） | 入りやすさ |
| `hours` | 文字列（OSM形式） | — |
| `closed_days` | 文字列 | — |
| `price` | 整数（円） | — |

`hours` と `closed_days` と `price` は軸に効かないが、**OSMに無いことが多く実用価値が高い**（37,193件のうち営業時間を持つのは一部のみ）。

## 5. 裏付けをどう数えるか

**同じ事実を主張する独立したドメインの数**を裏付け件数とする。

同一ドメインの複数ページは1件と数える。個人ブログ3件と公式サイト1件なら4件。

| 裏付け | 扱い |
|---|---|
| 0件 | 業態からの推定のまま。何も変えない |
| 1件 | 記録するが軸は変えない。表示は「1件の情報あり」 |
| 2件以上 | 軸に反映する。表示は「N件で確認」 |
| 公式サイト1件 | 営業時間・料金・定休日に限り、2件相当として扱う |

公式サイトを優遇するのは、市営温泉の料金のような事実について、自治体のページが個人ブログ2件より確かだからである。一方で「一人客が多い」のような主観を含む事実は、公式サイトが書かないので個人ブログの件数に頼る。

### 矛盾は消さない

竹瓦温泉について、ある情報源は「洗い場がない」と書き、別の情報源は「普通湯で頭や体を洗う」と書いていた。**どちらかを選んで表示してはならない。**

矛盾する主張は両方を記録し、その事実については軸を変えない。詳細シートに「情報が分かれています」と出す。

## 6. 軸をどう作り直すか

**上書きしない。推定値からの差分として持つ。**

```
実効値 = clamp(推定値 + Σ調整, 1, 5)
```

| 事実 | 調整 |
|---|---|
| `payment_method=ticket_machine` | 入りやすさ +1 |
| `payment_method=counter_person` | 入りやすさ −1 |
| `reservation=none` | 入りやすさ +1 |
| `reservation=required` | 入りやすさ −2 |
| `first_timer=custom_exists` | 入りやすさ −1 |
| `first_timer=easy` | 入りやすさ +1 |
| `clientele=local` | 入りやすさ −1 |
| `clientele=solo_common` | ひとり度 +1 |
| `counter_seats >= 1` | ひとり度 +1 |
| `silence=posted` | 静けさ +1 |
| `silence=observed` | 静けさ +1 |

調整の合計は軸ごとに **±2 まで**に制限する。1つの事実で3から5へ飛ぶのは、根拠に対して主張が強すぎる。

**推定値と実効値の両方を保持する。** 表示は実効値だが、詳細シートで「業態からの推定は3、確認した事実により4」と出せるようにする。何を根拠に変えたのかを隠さない。

## 7. 利用者に何を見せるか

一覧のカードは変えない。詳細シートに「確認できたこと」の節を足す。

```
確認できたこと                    3件の情報源で確認
  券売機あり            2件
  地元客が中心          2件
  入浴料 200円          別府市公式サイト
  情報が分かれています: 洗い場の有無
```

**出典URLは出す。** 主張の文章は出さない。「うちが確認した事実」であって「引用」ではないが、確かめたい人が辿れる必要がある。

調べていない施設には**「まだ調べていません」と明示する**。何も書かないと「調べた上で何も無かった」と読めてしまう。これは既存の失敗と同じ形である。

## 8. 仕組み

GitHub Pages は静的サイトなので、収集は**ビルド前の作業**である。実行時に検索することはない。

```
research_queue.py   調べる施設を優先度順に出す（既存）
        ↓
   検索と事実の抽出（MCPの検索APIを使う。人／エージェントが実行）
        ↓
curate.py           事実を検証して curated.json に書く（新規）
        ↓
build_data.py       裏付け2件以上の調整を軸に反映（既存を変更）
```

`curate.py` が守ること。**約束ではなくコードで守る。**

- 禁止ドメインの URL を拒否する
- 語彙にない事実を拒否する
- 同一ドメインを重複して数えない
- 調整の合計が ±2 を超えたら切り詰める
- 文章を保存しない（`claim` は語彙の値のみ。自由記述欄を持たない）

### 優先順位

`research_queue.py` は既にある。本フェーズでは当たりやすさを加味する。

1. 孤立している施設（そこしか無いので調べる価値が高い）
2. 穴場と判定された施設
3. 市営・公営の入浴施設（自治体サイトがあり必ず当たる）
4. 軸が境界値（3）の施設（判定を間違えやすい）

### 規模

初回は **300件**を目標とする。全体の 0.8% である。

少ないが、上の優先順位で選ぶので「調べる価値が高い施設」に集中する。そして**調べた件数を隠さない**。「37,193件中300件を確認済み」と出す。数を誇張しない。

## 9. 失敗の扱い

| 状況 | 挙動 |
|---|---|
| 禁止ドメインのURLが渡された | `curate.py` がエラーで停止。黙って捨てない（気づかず集め続けるため） |
| 語彙にない事実 | 拒否してエラー。勝手に近い値へ丸めない |
| 同じ施設で矛盾する事実 | 両方記録し、その事実の調整を0にする。詳細シートに「情報が分かれています」 |
| 裏付け1件 | 記録するが軸を変えない |
| 調べていない施設 | 「まだ調べていません」と明示 |
| `curated.json` の施設IDが現データに無い | ビルド時に警告して読み飛ばす。件数を報告する |

## 10. テスト

| 対象 | 方法 |
|---|---|
| 禁止ドメインの遮断 | 食べログ・サウナイキタイ・RettyのURLで例外が出る |
| 語彙の検証 | 未知の事実名・未知の値を拒否する |
| ドメイン重複 | 同一ドメイン3ページが裏付け1件になる |
| 調整の上限 | 事実を大量に積んでも軸の変化が±2に収まる |
| 矛盾 | 相反する事実があるとその軸を変えない |
| 公式サイトの優遇 | 営業時間・料金・定休日に限り1件で反映、他は反映しない |
| 表示 | 未調査の施設に「まだ調べていません」が出る／出典URLが出る／主張の文章が出ない |

## 11. 本フェーズに含めないもの

- 実行時の検索（静的サイトなので不可能）
- 全37,193件の網羅（実測により成立しないと判断）
- 食べログ・サウナイキタイ・Retty の利用
- 写真の取得
- HotPepper / Yahoo API（利用者のキー登録が必要）
