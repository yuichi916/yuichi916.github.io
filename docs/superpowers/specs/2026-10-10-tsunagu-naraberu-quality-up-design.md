# 『つなぐ×ならべる』商用級クオリティアップ 設計書

日付: 2026-10-10
前提: 2026-10-06 設計書（ルール・構成）と docs/tsunagu-naraberu-balance.md（現在の調整値）
方針（依頼主と合意）:
- 無料公開のまま、品質だけを商用級にする
- キャラは「女の子4人（各派2人）＋相棒マスコット2匹」。強さは全員同じで、見た目と声だけが違う
- 声は ElevenLabs

## 0. 進め方

4つの部分に分け、部分ごとに「実装→テスト→実画面の確認→公開の可否をうかがう」で進める。

| 順 | 部分 | 終わりの条件 |
|---|---|---|
| 1 | キャラ | 4人の立ち絵（表情7種）・選択用の全身・カットインがゲームに入り、品質チェックが全部合格 |
| 2 | 操作性 | キー設定・ゲームパッド・スマホのジェスチャー・先行入力・練習モードが動き、テストが通る |
| 3 | 仕上げ | 画面の流れ・設定・チュートリアル・戦績・紹介画像がそろい、PC/スマホでエラー0 |
| 4 | バランス | CPU5段の全段で両派が45〜55%、開幕20秒以内の決着が5%未満 |

ゲームの中身（盤・ダメージ・試合）を変えるのは 2（先行入力）と 4 だけ。1 と 3 は見た目・画面・音で、`fx.test.mjs` の「演出の有無で試合結果が変わらない」を守る。

### 1.2 絵の作り方

道具: ローカルの reForge（`127.0.0.1:7860`）。モデルは `waiIllustriousSDXL_v170`（WAI-Illustrious）。生成画像の利用はモデルのライセンスで認められている。

1. **スタイルブック**: `docs/tsunagu-naraberu-stylebook.md` に、画風・色・キャラごとの決まり（上の表）と、生成に使う共通プロンプト／ネガティブを書く。
2. **基本の1枚**（キャラごと）
   - txt2img、832×1216、白背景、腰から上（cowboy shot）、正面やや斜め、通常の表情
   - 候補を8枚作り、品質チェックで1枚選ぶ
3. **表情差分**: 基本の1枚の顔の範囲だけをマスクして inpaint（denoise 0.45〜0.6）。顔以外はそのままなので、別人にならない。
   - 7種: `normal` 通常 / `happy` 喜び（小連鎖） / `attack` 大連鎖（叫ぶ） / `ouch` 被弾 / `pinch` ピンチ / `win` 勝ち / `lose` 負け
4. **透過**: 白背景を抜く（rembg の isnet-anime、なければ白の塗りつぶし抜き＋縁の色にじみ処理）。
5. **書き出し**: 高さ720pxの透過 WebP（品質85）。
   - 置き場所: `assets/tsunagu-naraberu/chara/<id>/<expr>.webp`
   - 選択画面用 `select.webp`: 基本の1枚の全体
   - カットイン用 `cutin.webp`: `attack` の顔まわりを横長に切り出したもの
6. **品質チェック**: 確認用のエージェント4体で並列に検査し、全部が合格するまで作り直す。
   - 見る点: 手指・目・左右の差の崩れ、表情が意図どおりか、同じキャラに見えるか、露出、背景の抜け残り
7. 容量の目安: 1キャラ9枚 × 約60KB × 4人 = 約2.2MB

相棒マスコット（ぷにまる・カクたん）は、canvas の描画を描き直してかわいさを上げる（絵ファイルにしない＝軽く、自由に動かせる）。

### 1.3 声（ElevenLabs）

- モデル `eleven_turbo_v2_5`、`language_code: "ja"`
  - 短い掛け声が英語読みになるのを防ぐため（2026-07-20 に確かめた組み合わせ）
- 日本語は Python の requests で送る（curl だと文字化けする）
- 声の割り当て
  - 2人: 既知の日本語女性声（`JTlYtJrcTzPC71hMLOxo`＝Yuki、`HxuFAkkGVeQs1sDIMF5g`）
  - 残り2人: 依頼主が声の ID を指定する。届くまでは、絵と組み込みを先に進める
- 台詞（1人11本）: `select` 選ばれたとき / `start` 開始 / `c1`〜`c5` 連鎖1〜5段以上 / `ouch` 被弾 / `danger` ピンチ / `win` / `lose`
  - 台詞の文はキャラの性格に合わせて書き、`characters.js` に表示用の文と一緒に持つ
- 置き場所: `assets/tsunagu-naraberu/voice/<id>_<key>.mp3`
- 相棒マスコット: 言葉ではなく鳴き声の効果音にする。VOICEVOX の声はやめ、クレジットから外す
- 生成スクリプト: `_dev/tsunagu-naraberu/gen_voice_el.py`
- 異常検出: 尺÷字数の回帰残差で、読み飛ばし・英語読みを見つけて作り直す

### 1.4 ゲームへの組み込み

- `characters.js`: キャラ定義（ID・名前・派・色・台詞・ファイル名）。ほかのモジュールはここだけを見る
- 盤の横に立ち絵（大）と相棒（小）を置く。いまの `chara.js` の気分の仕組みで、表情を切り替える
  - 連鎖2〜3段 → `happy`、4段以上 → `attack`、おじゃま → `ouch`、ピンチ → `pinch`、勝ち負け → `win`/`lose`
- 4連鎖以上: 画面を横切るカットイン（`cutin.webp`＋集中線を canvas で描く）を0.8秒。演出の強さ「低」ではなし
- 2人が同じキャラを選んだら、2P側は色相をずらした色違いで描く（canvas の filter）
- スマホ: 立ち絵は自分のぶんだけ小さく置き、相手は顔アイコン

## 2. 操作性

### 2.1 入力
- **キー設定**: 全操作（移動4方向・A・B・一時停止）を、1P/2P それぞれ割り当て直せる。`localStorage` に保存。初期値はいまの対応表
- **ゲームパッド**（Gamepad API、standard mapping）
  - 十字キー・左スティック＝移動、A(0)＝A、B(1)＝B、X(2)＝B、Start(9)＝一時停止
  - 接続順に 1P/2P
- **連続移動**: 押しっぱなしで動き始めるまで（DAS、初期10刻み）と、連続で動く間隔（ARR、初期2刻み）を設定で変えられる

### 2.2 先行入力（ゲームの中身。テストで固定する）
- **つなぐ派**: 次の組が出るまで（消去中・おじゃま着地中）に押した回転を覚えておき、出た瞬間に回す（IRS）
- **ならべる派**: 入れ替えを押したとき、対象が浮遊中・落下中で入れ替えられなければ、最大6刻みのあいだ受け付け続ける
- いずれも人の手触りの改善。CPU は使わない（バランスに影響しない）

### 2.3 スマホ
- **つなぐ派のジェスチャー**（ボタンと併用。設定で切り替え）
  - 盤の上で横にすべらせる → 指の移動量ぶん列を動かす
  - タップ → 右回転（盤の左半分のタップは左回転）
  - 下へすばやくはじく → すぐ落とす。ゆっくり下へ → 速く落とす
- **振動**（navigator.vibrate、設定でオフ可）: 入れ替え・消去・おじゃま着地で短く
- **押せる範囲**: ボタンは最小 56px

### 2.4 練習モード
- 自分の盤だけで遊ぶ（相手なし・時間制限なし）
- 「おじゃまを降らせる」ボタン（6／12／30）、盤をリセット

## 3. 商用級の仕上げ

### 3.1 画面の流れ
読み込み（進み具合のバー）→ タイトル → モード選択 → キャラ選択 → VS 演出 → 対戦 → 結果

| 画面 | 中身 |
|---|---|
| 読み込み | 絵・音の読み込み率。初回だけ数秒 |
| タイトル | ロゴのアニメ、4人の立ち絵、「はじめる」 |
| モード選択 | CPUと対戦／ふたりで対戦（PCのみ）／練習／チュートリアル／戦績／設定 |
| キャラ選択 | 4人から選ぶ（派はキャラで決まる）。選ぶと `select` の声。CPU戦は相手とCPUの強さも選ぶ |
| VS 演出 | 2人の立ち絵が左右から入り「VS」。約2秒。キーで飛ばせる |
| 結果 | 勝ったキャラの `win` 立ち絵、成績（最大連鎖・送った攻撃・時間）、もう一回／キャラを選び直す／メニュー |

### 3.2 設定画面
- 音量: BGM・効果音・声（0〜100）
- 演出の強さ: 高／低
  - 低＝カットインなし、破片を減らす、揺れなし
- 揺れや点滅を抑える
  - OS の prefers-reduced-motion を初期値にする
- キー設定（2.1）、DAS・ARR、スマホの操作方式、振動
- 保存先: `localStorage` の `tn-settings-v2`。古い `tn-settings` は読み替える

### 3.3 チュートリアル
派ごとに、実際に操作しながら進める（約1分）。用意した盤面と課題を順に出し、できたら次へ進む。
- つなぐ派: 移動と回転 → 4つつなげる → 2連鎖を組む → おじゃまを消す
- ならべる派: カーソルと入れ替え → 3つ並べる → 2連鎖 → アクティブ連鎖（浮いている間に差し込む）→ せり上げ

### 3.4 戦績
キャラ別・CPU段別の勝敗、最大連鎖、1試合の最大攻撃、遊んだ回数。`localStorage`（`tn-records-v1`）。戦績画面で見られる。

### 3.5 磨き込み
- 画面の切り替え: フェード・スライド 0.25秒
- ボタン: 押したときの沈み込みと音
- 文字: 日本語の折り返しを整える（文節で改行）
- スマホの縦レイアウトを見直す（立ち絵・予告・時間の位置）
- 紹介画像: 1200×630 の OGP 画像を、キャラ入りで作り直す
- 軽さ: 375px のスマホ相当で 60fps 近くを保つ。立ち絵は読み込み後に ImageBitmap にして描く

## 4. バランス

- CPUの段: かんたん／やさしい／ふつう／つよい／おに
  - かんたん: 操作の待ちを長く、判断のぶれを大きく。はじめての人が勝てる強さ
  - おに: 2手読み・待ち短め
- 目標
  - 各段で、つなぐ派の勝率が 45〜55%（各段2000試合）
  - 同じ派どうしの1P勝率が 50% 付近
  - 開幕20秒以内の決着が、全段で5%未満
  - 平均試合時間: かんたん〜ふつうは 2.5〜4分、つよい・おには 1.5分以上
  - 段の並びの確認: 隣の段どうしで戦わせて、上の段が 65% 以上勝つ
- 測定: `balance.mjs` に「隣の段どうし」と「20秒以内の決着の割合」の出力を足す
- 調整は config の数値で行い、結果を `docs/tsunagu-naraberu-balance.md` に残す

## 6. 確かめ方
- 単体テスト（`node --test`）
  - 先行入力（つなぐ派の IRS、ならべる派の入れ替えの受け付け延長）
  - 設定の保存と読み替え
  - 戦績の集計
  - キー割り当ての読み替え
  - 練習モードのおじゃま投入
- 既存のテスト（71件）が全部通ること。演出の有無で試合結果が変わらないこと（`fx.test.mjs`）
- 実画面（Python Playwright＋Chrome）
  - PC幅・375px幅で、読み込みから結果まで通す
  - コンソールエラー0、はみ出しなし
  - 画面ごとにスクリーンショットを撮る
- 絵・声の品質チェック: エージェント並列で絵を検査し、声は尺の回帰残差で検査する
- バランス: 4章の目標を `balance.mjs` で測る

## 7. 今回やらないこと

## 8. 既知のリスク
- 生成画像で同じキャラに見えない → 表情は inpaint だけで作る。基本の1枚を固定する
- 声のキーに一覧の権限がない → ID は依頼主から受け取る。届くまで声は後回しにし、ほかを先に進める
- 立ち絵の容量で初回の読み込みが重い → WebP・720px・読み込み画面で吸収
