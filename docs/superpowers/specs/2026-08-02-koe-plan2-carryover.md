**未実施。** これは Plan 1 唯一の人手ゲートで、設計書 §11 のリスク表の最上段を決める。
`tryvoice` の5段ラダー、`synth-*` の命名、4×5=16本の生成——**ボイスパイプライン全体がこの判定に通ることを前提に組まれている。**

- 判定材料: `C:\tmp\koe_probe_out\audition.html`
- 判定基準: 0% → 100% を順に聴いて「壊れた声が組み上がっていく」と感じられるか
- 不合格なら: DSP方式を捨て、ElevenLabs に音素を欠落させた台詞を直接読ませる方式へ。設計書 §11 のリスク行のとおり

**実装中に設計から動いた点**（耳判定の対象）: 75%のピッチ揺らぎは設計書の ±40cent ではなく **±15cent**。±40 だと位相ボコーダの歪みが支配的になり「進むほど元の声に近づく」（`d75 < d50`）が壊れたため。片言に聞こえないなら、cent を戻すのではなく**揺らぎの方式自体を変える**（リサンプリング系かディレイ系ビブラート）のが正しい。
50%/75% のフレーム境界（90ms/120ms）にクロスフェードが無いので、「傷んだ声」ではなく「デジタルなブツ切れ」に聞こえないかも併せて確認する。

## B. 本番ボイスを載せる前に必ず閉じる

### B-1. メディアが途中で止まったときの番人が無い

`tryVoice()` と `playFinalVoice()` は `done` ガードで多重発火は防いでいるが、**タイマーが無い**。
`play()` が成功したあとバッファで停止すると `ended` も `error` も `rejection` も来ず、`locked` が `true` のまま永久に固まる。
いまは全アセットが404で `play()` が即 reject するため到達しない。**実mp3が載った瞬間に現実の経路になる。**

### B-2. タイトル声のゲート検査を「再生完了」まで締める

設計書 §10 は `currentTime` の実測を求めている。現在の E2E は `titlekoe.play()` が1回呼ばれたことまでしか証明していない（`title-koe.mp3` が存在しないため、それ以上は原理的に無理）。
**アセットが載ったら `reason === 'ended'` と `currentTime` を assert に格上げする。**

### B-3. タイトル声の尺は6秒未満にするか、メタデータ待ちを信頼する

ゲートの保険タイマーは `loadedmetadata`（または `readyState>=1`）から `duration+1.5s` に延長されるが、メタデータが取れない場合の床は6秒。

## C. 本番台本を書き始める前に閉じる

### C-1. `{narrator:'ren'}` の順序アサートが自己消去する

`step()` は**ビートを実行する前に** `st.beat` を保存する。だからアサートが throw した時点で保存位置は既に問題のビートを追い越しており、作者がリロードして「つづきから」を押すと**当該ビートが飛ばされて何事もなく続く**。
このガードは執筆フェーズを守るために存在するので、**執筆フェーズの前に効くようにする必要がある。**

### C-2. `finalKey()` の `||'a'` — 済（要確認）

非nullの未対応 `firstMain` は throw するようになった。`null`（まだ主素材未取得）は `'a'` にフォールバックする。

### C-3. `mem-NN` の範囲内タイポが検出できない

`MEMS` は `MEM_COUNT=24` から生成されるので、`mem-03` を `mem-08` と書き間違えても通る。
さらに悪いことに、**主素材を `mem-07` → `mem-13` と書き間違えると通ったうえで、プレイヤーが受け取る結末ボイスが変わる**（`finalKey()` は両方を対応表に持つ）。`final-a`〜`final-d` は許可リストに入っているので棚卸しからも見えない。
4か所×24枚の対応が確定したら、**IDごとの明示テーブル**に置き換える。

### C-4. `flashMem()` の404が無言

キーの誤りは throw するようになったが、**ファイルが無い場合**は CSS `background-image` なので `onerror` が無く、1400ms の黒画面が流れるだけで何も言わない。

### C-5. 同一ビートに2つの命令を書いたときの一般則

`{say}` と `{bgm}` については「先に dispatch される命令と同居したら throw」を実装済み（`assertNoLostKey`、禁止キーは `String(step)` から導出）。
**残り20個の命令については未実装。** 一般化には**従属キー表**が要る——`show`+`pos`/`expr`、`pickup`+`main`、`choose`+`timed`/`timeout`、`when`+`reply`、`say`+`text`/`v`/`ex` は同居が正当なので、単純に禁止すると壊れる。

## D. ガードの堅牢性（Plan 2 のどこかで）

- **`lostKeyConflicts()` の部分パース**: 導出失敗の床が `i < 1` なので、**全滅は大きな音で落ちるが、一部だけ拾えなかった場合は黙って禁止集合が縮む**。`if(b['bg'])` のような書き換えが1箇所あるだけで `bgm` の禁止集合が `['cg']` に縮み、いま直した欠陥が再び書けるようになる。キーごとに期待する先行集合をピン留めするのが安い
- **シーン免除が `say` にも効く**: `Array.isArray(b.beats)` でシーンを免除しているが、`say` ガードにも同じ免除がかかる。シーン直下の `say` は `enterScene()` が dispatch しないので死にデータであり実害は無いが、以前は捕まえていた
- **スロットロードだけ開始手順を手書きしている**: `tCont` は統一したが、スロットロード経路は `st=Object.assign(freshState(d.st), d.st); … enterScene();` のまま。save/load の不具合Bを生んだ重複の生き残り

## F. 承知のうえで残しているもの

- 移植由来の死にコード（`curColor`、`btns`、`smMode`、`<audio id="amb">`、`#fade`/`.black`）——移植元でも死んでいる
- `bgm_prep._duration()` が失敗時に `0.0` を返す（`sec` は試聴用の参考値）／`to_mp3()` が ffmpeg の stderr を捨てる
- `_walk` の循環検出が dict のみ（自己参照 list は `RecursionError`＝大きな音で落ちる）
- `audit()` を関数として直接呼ぶ経路には形状不一致ガードが無い（現時点で呼ぶ者はいない）
- E2E の `assert errors == []` が `unpkg` の three.js に依存している（オフラインで無関係に赤くなる）
- `koe_e2e_test.py` の `STALL_AFTER=25` は、本番台本が25秒超の `card.hold` を使うなら上げる必要がある
- `koe.html` がトップページと sitemap から未リンク（**公開はフェーズ6なので正しい**。ただし前作で「最大の作品がトップから1本もリンクされていない」状態を長く放置した前科があるので、公開時に必ず通す）
