## §1 一人客が本当に知りたいこと

研究の結論は「味・値段・雰囲気ではなく、**いま自分がそこに行って浮かないか**の一点」。

| 研究の記述 | 実装 |
|---|---|
| 3軸（ひとり度・静けさ・入りやすさ）を主指標に据えているのは正しい方向 | `scripts/hitori/scoring.py` の `AXES`、カードの3行表示 |
| 「入店後に何をすればいいか分からない不安」への対応が弱い | `core.entryFlow()` + `hitori.html` の `flowHtml()`。確認できた事実だけで動線を作る |
| **一点に直接答える入口が無い** | `hitori.html` の `renderNowCard()`。一覧の前に「いま行くなら」の一枚を出す |
| 同上（並べ替え） | `core.sortItems(items, 'fit')`。営業中 → ひとり度(重み2)+入りやすさ+静けさ → 距離 |

`renderNowCard()` は fit の先頭を選び、**なぜそれを選んだかを必ず書く**。
根拠を書かずに「おすすめ」とだけ出すのは、出典を示すという方針に反する。

## §2 入りにくさの扱い

| パターン | 実装 |
|---|---|
| (a) 物理設計で不安源を消す（一蘭型） | 施設を作れないので直接は不可。代替として、行ってから何が起きるかを先に見せる（`entryFlow` / `KIND_GUIDE` / 「いま行くなら」の手順） |
| (b) 先行者の体験で予行演習（サウナイキタイ型） | 投稿機能は持たない。代わりに個人の記録を収集側で必ず1件当たる方針にし、番台か券売機か・洗い場・荷物の置き場・客層・混み方を事実として持つ（`enrich.FACT_VOCAB`）。1,098ドメイン中108が個人の記録 |
| (c) 対象外を明示して不安を消す | 一人不可・閉業・住民専用・会員専用が独立2件以上で裏付けられた施設を一覧から外す（`enrich.EXCLUDING`）。**外した件数を画面に出す**（`summary.excluded_count` → 作り方の説明） |

## §3 写真が無くても成立するか

| 研究の記述 | 実装 |
|---|---|
| 数値の視覚化（SoundPrint型） | 3軸をバー＋数値で出す |
| 時間帯グラフ（Googleマップ型）の代替 | `core.busyBands()` / `busyHtml()`。24時間を3段階で色分けし、**業態からの推定であると必ず書く** |
| 写真の後付け調達はしない | 実装なし（意図的） |

## §4 信頼性の担保

研究は「複数の独立した情報源のクロスチェックという第三の方式」であり
「この位置づけは明確に打ち出す価値がある」と書いている。

- ページ冒頭の `.method` に、口コミを集めないこと・出典URLと件数を必ず出すこと・
  食い違いは両方出すこと・除外と指標変更だけ独立2件以上を条件にすることを明記。
- 実態より強く書かない。以前は「一致した事実だけを載せています」と書いていたが、
  事実4,380件のうち2ドメイン以上の裏付けは一部なので、書き直した。
- 収集で使えないサイト（自動アクセスを禁止しているもの）はコードで弾く
  （`enrich.BLOCKED_DOMAINS`、`normalize_facts.strip_blocked_urls`）。

## 研究に無いが、実装で必要になったもの

研究は既存サービスの分析なので、実データを集めて初めて必要になった語彙がある。

- `open_period` — 閉業でも休業でもないが、いつやっているか決まっていない施設
- `closes_on` — 閉業が発表されているが、その日はまだ来ていない施設
- `city` — OSM に所在地があるのは12.2%だけで、調べて分かった市区町村を記録する場所が無かった
- `footbath` — 足湯・手湯は服を脱がず番台も洗い場も無い。銭湯として出すと作法ガイドまで付く
