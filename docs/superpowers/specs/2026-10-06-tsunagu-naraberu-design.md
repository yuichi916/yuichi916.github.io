# 『つなぐ×ならべる』設計書（仮題）

日付: 2026-10-06
状態: 設計承認済み（会話）→ 本書レビュー待ち

## 1. 目的と成功基準

「4つつなげて消す落ち物（つなぐ派）」と「3つ並べて消す入れ替えパズル（ならべる派）」が、
**異なる盤のまま直接対戦する**ブラウザゲームを作る。核は「どちらの派を選んでも勝負が五分になる」こと。

成功基準:
- CPU同士・同じ強さの段で数千試合 → つなぐ派の勝率が **45〜55%**（やさしい／ふつう／つよい の全段）
- 同条件の平均試合時間が **2.5〜4分**
- 片方の派の上手さだけでは勝てない（どちらの派も自分の盤のスキルがそのまま勝敗に効く）
- ブラウザでコンソールエラー0、PC2人対戦・CPU戦・スマホ幅の表示がすべて動く

### 名前の扱い
「ぷよぷよ」「パネルでポン」は他社商標のため、ゲーム内・サイト・説明文で使わない。
呼称は「つなぐ派」「ならべる派」、消す物は「つぶ」「パネル」、妨害は「おじゃまつぶ」「おじゃまブロック」。

## 2. 遊び方の流れ

タイトル → モード選択（CPU戦／2人対戦）→ 各プレイヤーが派を選ぶ（同じ派どうしも可）
→ CPU戦なら強さ選択（やさしい／ふつう／つよい）＋ハンデ → 対戦 → 結果（もう一回／派を選び直す）

## 3. 共通ルール

- 盤: どちらも幅6×高さ12。色は5色、色覚配慮で各色に形マーク（●▲■◆★）。
- 時間: 両盤とも**毎秒60回の固定刻み**で同時に進む（リアルタイム）。
- 負け条件
  - つなぐ派: 出現位置（左から3列目・最上段）がふさがった時点
  - ならべる派: パネル（おじゃま含む）が最上段に届いた状態で、猶予 `topGraceSec` が切れた時点（消去中・おじゃま解凍中は猶予が減らない）
  - 同じ刻みで両者が負けたら引き分け
- 終盤加速: 開始 `feverStartSec`（初期90秒）から、`feverStepSec`（15秒）ごとに両者の攻撃倍率を `feverStepMul`（+0.1）ずつ上げる（上限 `feverMaxMul` 2.0）。

## 4. つなぐ派の盤

- 2個1組が出現し、左右移動・左右回転・高速落下・自動落下（`tsunaguFallSec` 秒/マス、初期0.5）。壁際では回転時に1マス押し出し、左右とも詰まっていれば上下反転。
- 着地後、浮いたつぶは落ちる。同色が上下左右に4つ以上つながると消える。消えたあと落下→再判定を繰り返し、各段を1連鎖と数える。
- 1連鎖ごとに消去演出 `tsunaguPopSec`（初期0.5秒）。この間は次の組が出ない。
- おじゃまつぶ: 色を持たず、隣で同色が消えたときに一緒に消える。

## 5. ならべる派の盤

- 横2マスのカーソルで左右のパネルを入れ替える（片方が空でも可）。
- 縦か横に同色3つ以上そろうと消える。消えた空きに上のパネルが落ち、そこで新たにそろえば連鎖。
- 同時に4つ以上消えたらコンボ。
- 自動せり上がり: `naraberuRiseSec` 秒/行（初期8秒、開始から180秒かけて3秒まで線形に速くなる）。手動せり上げボタンあり。
- 消去中（1段あたり `naraberuClearSec`、初期0.9秒）はせり上がりを止める。
- おじゃまブロック: 隣接するパネルが消えると「解凍」が始まり、下の1行が普通のパネルに戻る（残りは1行縮んだブロックとして残る）。

## 6. 攻撃（共通ダメージ）

### 6.1 ダメージ値D
ダメージ値Dの1単位は、おじゃまつぶ1個＝おじゃまブロック1マスにあたる（変換率1.0のとき）。

**つなぐ派**（1連鎖ごと）:
```
D = 10 × n × max(1, CP[c] + GB(各グループの大きさ) + CB(色数)) / 70 × atkMulT
```
- n は消去数、c は連鎖段
- CP（連鎖ボーナス）= [0, 8, 16, 32, 64, 96, 128, 160, …以降+32]
- GB（連結ボーナス）= 大きさ4→0, 5→2, 6→3, 7→4, 8→5, 9→6, 10→7, 11以上→10
- CB（色数ボーナス）= 1色→0, 2→3, 3→6, 4→12, 5→24
- 端数は持ち越す（小数のまま貯めて、整数分だけ送る）

**ならべる派**:
- コンボ（その段の同時消去数 n≥4）: `D_combo = COMBO[n] × atkMulN`
  - COMBO = 4→3, 5→4, 6→5, 7→6, 8→7, 9→8, 10→10, 11→12, 12以上→n
- 連鎖（段 c≥2 の各段）: `D_chain = chainStepN × (c−1) × atkMulN`（chainStepN 初期6＝1段で横1行分）

いずれも最後に終盤加速の倍率とハンデ倍率を掛ける。

### 6.2 相殺と予告
- 各プレイヤーは「受ける予定の攻撃（予告）」をDの合計で持つ。
- 送るときは、まず自分の予告からDを差し引き、余りを相手の予告に足す。
- 予告は盤の上に目盛りで表示する（つぶ6個＝1行の目安アイコン）。

### 6.3 着弾（受ける側の盤に合わせて変換）
- **つなぐ派が受ける**: 次の組を置いて連鎖が終わった時点で、予告を `round(D × convT)` 個のおじゃまつぶに変換して落とす（1回最大30個。残りは予告に残る）。列はランダム、6の倍数分は均等に。
- **ならべる派が受ける**: 予告に入ってから `naraberuLandSec`（初期3秒）経ち、かつ消去中でないときに着弾する。`round(D × convN)` マスを次のように分ける。
  - 6マスごとに1行として、まとめて高さkの全幅ブロック1個にする（kの上限は12）
  - 余り r が3以上なら幅 r・高さ1のブロック1個
  - 余り r が2以下なら予告に残す

## 7. 調整つまみとハンデ（`config.js` に集約）

| つまみ | 初期値 | 役割 |
|---|---|---|
| convT | 1.0 | ならべる派→つなぐ派の変換率 |
| convN | 1.0 | つなぐ派→ならべる派の変換率 |
| atkMulT / CP表の伸び | 1.0 / 上記 | つなぐ派の連鎖ボーナスの伸び方 |
| atkMulN / chainStepN | 1.0 / 6 | ならべる派の連鎖ボーナスの伸び方 |
| naraberuRiseSec | 8→3 | せり上がりの速さ |
| tsunaguFallSec | 0.5 | 自動落下の速さ |

そのほか時間定数（tsunaguPopSec / naraberuClearSec / naraberuLandSec / topGraceSec / fever系）も同じファイルに置く。
ハンデは −2〜+2 の5段階で、1段あたりそのプレイヤーの攻撃倍率を ±20% する。

## 8. CPU

強さの段は2つの軸で決め、両派で同じ物差しを使う。

| 段 | 考える深さ | 1操作ごとの待ち | 考え始めるまで |
|---|---|---|---|
| やさしい | 1手 | 12刻み | 30刻み |
| ふつう | 1手＋簡易の連鎖見込み | 6刻み | 15刻み |
| つよい | 2手 | 3刻み | 6刻み |

- **つなぐ派AI**: 置ける場所（最大22通り）を盤の複製で試し打ちして評価する。評価は連鎖数・消去数・同色の隣接 − 最大高さ・凸凹・穴・出現列の高さ。予告が多いときは即時発火を重く見る。
- **ならべる派AI**: 入れ替え1手（最大60通り）と、つよいでは2手の組み合わせを試し打ちして評価する。評価は消去・連鎖・おじゃま解凍 − 最大高さ・凸凹。カーソル移動1マスにも1操作の待ちがかかる（操作の速さを人間並みにそろえるため）。
- 評価の重みも `config.js` に置く。

## 9. 操作

| | 1P | 2P |
|---|---|---|
| 移動 | W A S D | ↑ ← ↓ → |
| つなぐ派: 左回転／右回転 | F／G | ;／' |
| ならべる派: 入れ替え／せり上げ | F／G | ;／' |

- つなぐ派のWと↑は「すぐ落とす」。
- スマホはCPU戦のみ。つなぐ派は画面下のボタン、ならべる派はパネルを左右になぞって入れ替え＋せり上げボタン。
- 画面: PCは左右2盤＋中央に予告と時間。スマホは自分の盤を大きく、相手の盤は縮小で上に置く。

## 10. 構成

- 本体: `tsunagu-naraberu.html`（サイト子ページ。index.html の nav・一覧に登録）
- ロジック: `assets/tsunagu-naraberu/*.js`（ESモジュール。HTMLとNodeテストが同じファイルを読む）

| ファイル | 役割 | DOM依存 |
|---|---|---|
| config.js | つまみ・時間定数・AI重み・ハンデ | なし |
| rng.js | シード付き乱数（mulberry32） | なし |
| tsunagu.js | つなぐ派の盤 `createTsunagu(cfg, rng)` → `step(input)` / `receive(n)` / 状態 | なし |
| naraberu.js | ならべる派の盤（同じ形のインターフェース） | なし |
| damage.js | D計算・相殺・予告・変換 | なし |
| match.js | 2盤＋ダメージを固定刻みで進め、勝敗・試合時間を出す | なし |
| ai-tsunagu.js / ai-naraberu.js | 盤の状態→入力列 | なし |
| render.js / input.js / audio.js / ui.js | 描画・キー/タッチ・WebAudio・画面遷移 | あり |
| tools/balance.mjs | CPU対CPU大量実行（worker_threads）→勝率・試合時間の表、つまみの探索 | なし |
| tests/*.test.mjs | `node --test` 単体テスト | なし |

- 両盤は同じインターフェースにする: `step(inputs)` は1刻み進めて、その刻みで発生した攻撃イベント `{D, chain}` を返す。`receive()` は着弾、`isDead()` で負け判定。match.js は派の違いを知らない。
- 乱数はプレイヤーごとにシードを持つ。同じシード＋同じ入力列なら同じ試合を再現できる（バランス測定とバグ再現に使う）。

## 11. 確かめ方

1. **単体テスト**（`node --test`）。手で答えを出した盤面でassertする。
   - つなぐ派: 4連結の消去、5連結、2色同時、3連鎖の段数とD値、おじゃまの巻き込み消去、回転の壁押し出し
   - ならべる派: 横3・縦3・L字5（同時5＝コンボ）、落下連鎖2段のD値、空きマスとの入れ替え、せり上がりと消去中停止、ブロック解凍
   - damage: 相殺で予告が減る／余りが相手に行く、ならべる派向けの分割（6・9・14・2マス）、端数の持ち越し
   - match: 同じシードで2回まわして結果が一致する
2. **バランス測定**（`tools/balance.mjs`）
   - 各段で、つなぐ派CPU対ならべる派CPUを最低2000試合まわす
   - 勝率（95%信頼区間つき）と平均試合時間を出す
   - 基準を外れたらつまみを探索し、最終の表を `docs/tsunagu-naraberu-balance.md` に残す
   - 同じ派どうしの対戦（ミラー）が50%前後になることも確かめる。勝敗の偏りがシードや先後の不具合でないことの確認用
3. **実画面**: ローカルサーバで開き、次を確かめてスクリーンショットで見せる。
   - コンソールエラー0
   - CPU戦を両派で完走
   - 2人対戦のキー操作
   - スマホ幅（375px）の表示とタッチ操作

## 13. 既知のリスク

- 「CPUの腕前が両派でそろっている」ことは仮定にすぎない。人間同士ではずれる可能性があるので、ハンデ設定で逃がす。公開後に実際の対戦で見直す。
- ならべる派の2手探索は候補が3,600通りになる。つよいだけに限定し、時間を測って重ければ枝刈りする。
