# ひとり歓迎マップ → 検索アプリへの再設計

- 日付: 2026-08-04
- 状態: 設計承認済み・実装計画待ち
- 前提: `2026-08-02-hitori-map-design.md`（実装済み・デプロイ済み）
- 成果物: `C:\projects\yuichi916.github.io\hitori.html` ほか

## 1. 何を変えるのか

現行版は「日本のどこがひとりに優しいか」を見る**読み物**として作った。県別ヒートマップが主役で、施設一覧はその付属物だった。

今回はこれを**「今の自分に合う一人向け施設を探す道具」**へ作り替える。主役は現在地から近い順の一覧であり、地図は補助に降りる。

利用者の問いが変わる。

- 旧: 「日本のどこがひとりに優しいのか」
- 新: **「今いるここから、ひとりで落ち着ける場所はどこか」**

ヒートマップは捨てない。「全国で見る」タブへ移す。俯瞰の読み物としての価値は独立して存在し、探す用途とは役割が違う。

## 2. 決定事項

| 論点 | 決定 |
|---|---|
| 入口 | 現在地から近い順のリスト |
| 「自分に合う」の軸 | ひとり耐性 / 静けさ / 入りやすさ の3軸 |
| 穴場の定義 | 周囲のチェーン比率が高い場所に立つ非チェーン店 |
| サイト内完結 | 施設詳細をサイト内シートで完結。地理院タイルの地図を内蔵 |
| 外部地図リンク | 座標ではなく**店名**で Google マップを検索 |
| 外部データ統合 | **今回は含めない**（フェーズ2。API キー登録が前提のため） |
| 営業中フィルタ | 既定では使わない（被覆率16.6%）。バッジ表示＋明示的オプトイン |

## 3. データ源の調査結果（2026-08-04 実測）

ユーザー要望にあった食べログ・サウナイキタイは使えない。代替と合わせて調べた結果は以下。

| 候補 | 状態 | 一人向け判定に使えるもの |
|---|---|---|
| **地理院タイル**（国土地理院） | ✅ 無料・キー不要・実測200 | 地図タイル z5-18。出典明記のみで利用可 |
| HotPepper グルメAPI | ✅ 無料・現行 | 緯度経度+半径300m〜3km、ジャンル、予算、営業時間、個室、禁煙、席数 |
| Yahoo!ローカルサーチAPI | ✅ 無料・現行 | 全国POI（電話帳＋オーナー投稿） |
| Google Places API | ⚠️ 有料 | 評価・レビュー数。キャッシュ30日制限・表示要件あり |
| ぐるなびAPI | ❌ 無料枠は2021-06-30終了 | 現在は法人有料のみ |
| 食べログ | ❌ 規約でスクレイピング禁止 | — |
| サウナイキタイ | ❌ 公開APIなし | — |

**HotPepper API に「カウンター席あり」フィールドは存在しない。** サイト上には出ている属性がAPIには落ちていない。自由文メモから拾う形になるため、期待値は下げておく。

外部API統合はフェーズ2に回す。理由は2つ。HotPepper も Yahoo も**本人によるキー登録が必要で今日は着手できない**こと。そして情報量を増やしても探せなければ使われないこと。

### 既存データの被覆率（2026-08-04 実測、38,012件）

| タグ | 件数 | 被覆率 |
|---|---|---|
| `opening_hours` | 6,321 | **16.6%** |
| `website` | 4,999 | 13.2% |
| `phone` | 4,557 | 12.0% |
| 住所タグ | 4,990 | 13.1% |

カテゴリ別の `opening_hours` は eat 19.3% / bath 17.7% / stay 13.3% / play 8.7%。

**この数字が「営業中のみ」を既定フィルタにできない根拠。** 既定で有効にすると83%が消え、探せる店が激減する。営業状態はバッジで出し、絞り込みは明示的なオプトインにする。

## 4. 画面

### 4.1 トップ（探す）

開いた直後に位置情報を要求する。許可されれば現在地から近い順、拒否・失敗・タイムアウトなら地名検索欄と「全国で見る」へ落とす。**位置情報なしでも機能が死なないこと**が要件。

絞り込みは3つに絞る。増やすと使われない。

1. **カテゴリ** — 湯・サウナ / カウンター飲食 / ひとり娯楽 / ひとり滞在
2. **距離** — 徒歩5分 / 10分 / 20分 / 指定なし（80m/分で換算し、400m / 800m / 1600m）
3. **ひとり条件** — 「一人が標準のみ」「静かなところ」「作法不要」（3軸それぞれの下限）

距離は**直線距離**で計算する。実際の徒歩距離はこれより長い。「徒歩5分」は目安であり、画面には「直線400m」も併記して誤解を避ける。

この3つの下に、控えめな2つのトグルを置く。上部の主フィルタには含めない。

- **営業時間が分かる店だけ** — 既定オフ。§3のとおり `opening_hours` の被覆率は16.6%しかなく、既定で有効にすると83%が消える。オンにしたときは「6,321件中」のように母数を出す
- **信頼度** — 現状ほぼ全件が◌のため、上部に置くと邪魔になるだけ

リストの各行に出すもの: 名前、業態、**徒歩◯分と方角**、3軸バッジ、営業状態バッジ、チェーン/穴場チップ。

### 4.2 施設詳細（サイト内シート）

一覧の行をタップするとシートが開く。**ここで完結させる。** 外部へ飛ばさずに分かること:

- 名前・業態・3軸バッジと各軸の一言説明
- 徒歩◯分（80m/分）・直線距離・方角
- 営業時間（あれば）と現在の営業状態
- 穴場スコアと**その理由**（例「周辺12件中10件がチェーン」）
- 電話・サイト（あれば）
- 地理院タイルの地図。現在地と施設の両方にピン
- curated 由来の一言と出典

末尾に「経路を調べる」として Google マップへのリンクを置く。**座標ではなく店名で検索する**。

```
https://www.google.com/maps/search/?api=1&query=<店名>+<市区町村名>
```

座標だけを渡すと地図上に無名のピンが立つだけで、店の情報にも経路にもたどり着けない。店名で検索させれば Google 側の店舗ページに着地する。市区町村名を足すのは同名店の誤爆を減らすため。市区町村が不明な場合は都道府県名で代用する。

### 4.3 全国で見る（旧トップ）

現行の県別ヒートマップ・ランキング・県詳細をそのままタブへ移す。実装済みのものを壊さない。

### 4.4 地図

MapLibre GL JS ＋ 地理院タイル（`https://cyberjapandata.gsi.go.jp/xyz/pale/{z}/{x}/{y}.png`、z5-18、PNG）。

APIキー不要、無料、政府提供。出典表記を地図上に常設する。

```
出典: 地理院タイル（https://maps.gsi.go.jp/development/ichiran.html）
```

淡色地図（pale）を使う。標準地図（std）は色が強く、施設ピンが埋もれる。

## 5. 3軸スコア

現行の `score` 1軸を3軸へ分解する。すべて業態から決定的に決まり、`curated.json` で個別に上書きできる。

日本では業態が静けさと作法をかなり正確に予測する。図書館は静かで作法不要、立ち飲みは声を出す場で常連文化がある、一蘭は静かだが食券と記入用紙の作法がある、銭湯は静か寄りだがかけ湯の作法がある。この対応を表にする。

| kind | solo | quiet | easy | 備考 |
|---|---|---|---|---|
| standing（立ち食い・立ち飲み・角打ち） | 5 | 2 | 2 | 常連文化・暗黙の作法 |
| yakiniku_solo（ひとり焼肉） | 5 | 4 | 4 | |
| netcafe（ネットカフェ個室） | 5 | 5 | 5 | |
| sauna | 5 | 5 | 3 | 黙浴・水風呂の作法 |
| ramen | 4 | 4 | 3 | 食券機 |
| gyudon | 4 | 4 | 4 | |
| soba_udon | 4 | 4 | 3 | |
| curry | 4 | 4 | 4 | |
| sento（銭湯） | 4 | 4 | 3 | かけ湯 |
| onsen（日帰り温泉） | 3 | 4 | 3 | |
| karaoke | 4 | 2 | 4 | 声を出す場 |
| library | 4 | 5 | 5 | |
| cinema | 3 | 5 | 5 | |
| museum | 3 | 5 | 5 | |
| hostel | 3 | 3 | 3 | |

- `solo`（ひとり耐性）: 5=一人が標準 / 4=一人が多数 / 3=一人でも浮かない
- `quiet`（静けさ）: 5=会話が発生しない / 4=静か寄り / 2=声を出す場
- `easy`（入りやすさ）: 5=作法不要 / 4=ほぼ不要 / 3=軽い作法（食券機・かけ湯） / 2=常連文化

チェーン加点は `solo` にのみ効く（現行どおり +1、上限5）。エビデンス加減も `solo` に効く。`quiet` と `easy` は業態と curated の明示指定のみで決まる。チェーンかどうかは静けさや作法とは無関係だからである。

`curated.json` で `"quiet": 2` のように軸ごとに上書きできる。

### 収録条件

`solo >= 3` を維持する。3軸のうち solo だけが収録可否を決める。

## 6. 穴場スコア

**定義**: ある施設の半径500m以内にある同カテゴリ施設のうち、チェーンが占める割合。

```
hidden = 周辺のチェーン件数 / 周辺の同カテゴリ件数     （自分自身を除く）
穴場と呼ぶ条件: chain == 0 かつ 周辺件数 >= 3 かつ hidden >= 0.6
```

駅前が牛丼屋とチェーン居酒屋で埋まっている中に1軒だけ残っている立ち食いそば、が上位に来る。

ビルド時に全件計算する。県境をまたぐ半径500mの取りこぼしを避けるため、**計算は県別ではなく全国の点集合に対して行う**。37,193件の総当たりは避け、0.01度（約1.1km）のグリッドに入れて近傍セルだけを見る。

各施設に `hidden`（0.0〜1.0、小数2桁）と `hidden_n`（周辺件数）を持たせる。画面には理由を出す。

> 穴場度 83%（周辺12件中10件がチェーン）

`hidden_n` が3未満の施設は穴場判定の対象外とし、`hidden` は 0 とする。周辺に2件しかない場所で「100%チェーン」と言っても意味がないためである。

## 7. 近傍探索のアーキテクチャ

**全国データを読み込まずに現在地から近い順を出す。**

1. `navigator.geolocation` で現在地を取る（タイムアウト10秒）
2. 既存の `prefectures_svg.json`（63KB、読み込み済み）へ現在地を投影し、**点内包判定で都道府県を決める**
3. その県と**隣接県**の `pref/NN.json` を取得する
4. ハーバサイン距離で並べ替える

投影は可逆である。`bounds` に `minx / miny / scale / lat0` があるため、緯度経度から SVG 座標へ前進変換して判定すればよい。

県境ポリゴンは簡略化されている（許容誤差0.012度≒1.3km）ため、県境付近では判定が1km程度ずれうる。隣接県も読むので実害はない。点内包がどの県にも当たらない場合（海上・国外）は**重心が最も近い県**へフォールバックする。

隣接関係はビルド時に生成する。`japan.geojson` の頂点を0.05度グリッドに入れ、**異なる県の頂点が2km以内にある県同士を隣接とみなす**。結果を `data/hitori/neighbors.json`（47エントリ、数KB）へ書き出す。

指定距離内の結果が3件未満の場合のみ、隣接県のさらに隣（2ホップ）まで広げる。人口希薄地域への対応であり、通常は発生しない。

### 読み込み量

東京都のファイルは466KB（gzip 127KB）。東京にいる利用者は東京＋神奈川・埼玉・千葉・山梨を読むことになり、合計で1MB前後（gzip 250KB前後）になる。

これを体感させないため、**取得を段階化する**。まず自県だけを取得して一覧を描画し、隣接県は後から取得して結果へ差し込む。利用者は自県の結果を待ち時間ほぼゼロで見られ、隣接県の店は数百ミリ秒後に現れる。県境付近にいる場合だけ後半が効く。

差し込み時に一覧が飛び跳ねないよう、追加は**並べ替え済みの位置へ挿入**し、表示中の先頭項目はスクロール位置を保つ。

## 8. データスキーマの変更

### pref/{code}.json

```json
{
  "pref": 13, "name": "東京都", "updated": "2026-08-04",
  "fields": ["id","name","lat","lon","cat","kind","solo","quiet","easy","conf","chain","hidden","hidden_n","city","oh","note"],
  "items": [
    ["n1234567890","一蘭 渋谷店",35.65894,139.70043,"eat","ramen",5,4,3,2,1,0.0,8,"渋谷区","11:00-23:00","仕切りカウンター12席"]
  ]
}
```

- `score` を `solo` / `quiet` / `easy` の3列に置き換える
- `hidden`（穴場度 0.0-1.0）と `hidden_n`（周辺件数）を追加
- `city`（市区町村名）を追加。Google マップ検索の精度向上と表示用。OSM の `addr:city` があれば採用、なければ空文字
- `oh`（`opening_hours` の生値）を追加。無ければ空文字

### summary.json

`counts` / `density` の構造は変えない。既存の「全国で見る」タブがそのまま動く。

### neighbors.json（新規）

```json
{"13": [11,12,14,19], "1": [2], ...}
```

## 9. 失敗の扱い

| 状況 | 挙動 |
|---|---|
| 位置情報を拒否された | 地名検索欄と「全国で見る」を出す。エラー扱いにしない |
| 位置情報がタイムアウト（10秒） | 同上。「位置情報が取れませんでした」と理由を出す |
| 現在地が日本国外 | 「日本国内のみ対応しています」と伝え、全国表示へ |
| 県ファイルの取得失敗 | その県だけエラー表示し、取得できた県の結果は出す |
| 地理院タイルの取得失敗 | 地図領域にプレースホルダと出典を出す。一覧と詳細は生かす |
| `opening_hours` が無い | 「営業時間不明」と明示する。営業中と偽らない |
| 指定距離内に0件 | 「徒歩20分以内に該当なし」と距離を上げる導線を出す |

`opening_hours` の解釈は OSM の書式に完全対応しない。`Mo-Fr 11:00-14:00,17:00-22:00` のような基本形のみ扱い、`PH` や `sunset` などが含まれる値は**解釈を諦めて「営業時間不明」として扱う**。誤って「営業中」と出すより、分からないと言うほうがましである。

## 11. v1に含めないもの

- **HotPepper / Yahoo / Google Places の統合**（フェーズ2。キー登録が前提）
- 食べログ・サウナイキタイのスクレイピング（規約違反のため恒久的に行わない）
- 経路案内そのもの（外部に委ねる）
- ユーザーアカウント・お気に入りの同期（localStorage のみ）
- 滞在できる長さの軸（今回の3軸に含めない判断をした）
- 駅からの距離（穴場の定義をチェーン比率に決めたため不要）
