# cabin.html 物語モード「灯を継ぐもの」設計書

日付: 2026-07-07
状態: ユーザー承認済み(核・アーク・機構・実装方針すべて確認済み。「推奨案のまま最後まで実装」指示あり)

## 1. 目的

cabin.html に、灯里(ともり)と蒼(そう)と一緒に「この小屋の謎」を解くアドベンチャーゲーム風の物語モードを追加する。3章の選択肢対話ADVで、ゴールは「火を次の誰かに渡す」。エンディングで感動・涙を誘う。既存の360°小屋・環境音・BGM・瞑想・マーカーは非破壊で温存し、物語モードは任意で重なるレイヤー。

## 2. 確定要件(ユーザー回答)

| 論点 | 決定 |

| 謎解き形式 | **選択肢対話中心**。軽い観察ビートを各章1回 |

## 3. 物語アーク

**タイトル**: 「灯を継ぐもの」— 灯里と蒼と、小屋の謎

**背景(hollow-tale直結)**: この小屋の火は消えない。道に迷い消えるつもりでたどり着いた人のため、いつも火が灯り茶が用意されている。灯里と蒼はかつて雪の夜に消えるつもりでここへ来た二人。火と、互いに救われ、去った灯守の役目を継いだ。今、火が弱り、次の灯守を待っている。プレイヤーもこの小屋に導かれたひとり。

- **第一章「灯る」** — なぜ火は消えないのか。灯里・蒼と話し、小屋を見回す(暖炉の茶/二つの椅子/窓の外の雪)。「誰かが来るのを知っていた」ことに気づく。選択で二人が少しずつ心を開く。BGM=夜のほとり。
- **第二章「秘密」** — 二人の正体。かつて同じ目をしてここへ来て、火を挟んで出会い、「消えちゃおうと思ったの」と打ち明け合った夜。互いと火に救われ灯守を継いだ。選択でプレイヤーが自分の痛みをそっと重ねる。BGM=水底の記憶。
- **第三章「継ぐ」** — 火が弱り、二人が去る時が近い。「火を継いでくれる?」。継ぐ選択→火が燃え上がり、灯里と蒼が「ありがとう」と微笑んで安らかに光になる。プレイヤーが新しい灯守になり、次の誰かのために火を灯し茶を用意する。BGM=結びつける絆。

**感動の核**: あなたも一人じゃなかった。誰かが火を灯して待っていてくれた。今度はあなたが次の誰かのために火を残す。孤独の連鎖を、あたたかさの連鎖に変える。

## 4. ゲーム機構

- **画面**: 360°の小屋(焚き火・環境音そのまま)を背景に、下1/3に対話ボックス(羊皮紙トーン、既存caption風)。左右に灯里・蒼の小さな立ち絵、話者がふわっと明るくなる。ボックス=話者名+セリフ+選択肢。
- **進行**: セリフ送り(クリック/タップ/Space/→)。節目で2-3択。**どの選択でも必ずエンディングに到達**(分岐で詰ませない)。選択は結末を変えず感情の手ざわりを変える。
- **観察ビート**: 各章1回「小屋を見回す」。360°の3点(暖炉の茶/二つの椅子/窓の外の雪)を順不同クリック→短い気づき独白→章が進む。既存のraycasterクリックと同系統。
- **ぬくもりの記録**: 選択のたび内部カウンタ `lit` を+1(絆の蓄積)。派手ゲージにせず、最終章で「あなたが灯した灯: N」と静かに見せる。分岐には使わない。
- **起動と保存**: ゲート+小屋内HUDに「小屋の謎をとく」ボタン。`localStorage: cabin_story = {chapter, beat, lit, cleared}`。途中再開・「はじめから」可。物語モード中は瞑想/マーカーHUDを隠し、終了で元の小屋へ戻る。
- **エンディング演出**: 継ぐ選択→焚き火が大きく燃え上がる(既存 CabinRoom の炎/呼吸APIで一時強調)→灯里と蒼の立ち絵がゆっくり光に溶ける(CSS opacity+blur+bright)→暗転→白文字で締めの言葉+「あなたが灯した灯: N」→静かに小屋へ戻り、暖炉に新しい茶。`cleared=true` 保存。

## 5. コード構造(A案: 自己完結モジュール)

cabin.html 内に追加(既存は非破壊)。約350-450行。

### 5.1 台本データ `STORY`(JSデータ)
```js
const STORY = {
  ch1: { title:'灯る', bgm:'story-ch1-yoru-no-hotori.mp3', beats:[ ...Beat ] },
  ch2: { title:'秘密', bgm:'story-ch2-minasoko.mp3',       beats:[ ...Beat ] },
  ch3: { title:'継ぐ', bgm:'story-ch3-kizuna.mp3',         beats:[ ...Beat ] },
};
```
Beat(判別可能union):
- 台詞: `{ say:'tomori'|'sou'|'narr'|'you', text:'…' }`
- 選択: `{ choose:[ {label:'…', reply:[Beat...] } , ...] }`  (reply後、本流へ合流)
- 観察: `{ look:{ prompt:'小屋を見回す', spots:[{key,label,line}], done:'…' } }`
- 演出: `{ fx:'flareFire'|'dissolveGuides'|'fadeBlack'|'newTea' }`
- 章末: `{ end:true }`(次章へ or エンディングへ)

台本は §3 のアークに沿い、各章の要点セリフを全て書き切る(プレースホルダ禁止)。

### 5.2 `StoryEngine`(IIFE)
```
StoryEngine = {
  start(fresh?), resume(), advance(), choose(i), lookSpot(key),
  render(beat), save(), load(), clear(),
  _state:{ch, beat, lit, stack}
}
```
- `render(beat)` が `#story` レイヤーへ描画(話者ハイライト、選択肢ボタン、観察ホットスポット)。
- 台詞は1文ずつ送り。選択は reply を積んで合流(stackで管理)。
- 章の bgm を `#story-bgm` audio で crossfade 再生(0.42 vol)。
- 観察ビートは既存の world/marker と別レイヤーの半透明ホットスポット(下記 §5.4)。
- save/load は localStorage `cabin_story`。

### 5.3 DOM(cabin.html に追加)
- `<div id="story">` 全画面透明レイヤー(pointer-events制御)。子: `.story-box`(対話), `.story-guide.left/.right`(立ち絵 assets/guide-boy.png / guide-witch.png), `.story-choices`, `.story-look`(観察ホットスポット), `.story-fx`(暗転/白文字)。
- `<button id="storyStart">小屋の謎をとく</button>`(ゲートと小屋内HUDに配置。既存HUDの並びに合わせる)。
- `<audio id="story-bgm" loop>`。
- CSS は既存 caption/ gate のトーン(Shippori Mincho, --ash, --lantern)に合わせる。話者色: 灯里=#f0d6e0 / 蒼=#cfe0f4(既存の掛け合いと統一)。

### 5.4 既存との連携(非破壊)
- 起動時 `document.body.classList.add('story-mode')`。CSSで `#hud`・マーカー・医想UIを隠す(既存 `__skipHud` があれば利用)。終了で解除。
- 背景の焚き火・環境音・パノラマはそのまま生かす(CabinRoom は触らない)。
- エンディングの炎強調は `window.CabinRoom.setBreath()` かフォールバックで CSS。無ければ static。
- 物語BGMは既存の音楽パネルと排他(物語中は既存BGMを止める; 終了で復帰は求めない=シンプル)。

## 7. エラー処理
- localStorage 不可(プライベート): try/catch で進行保存は揮発、プレイは継続。
- BGM 再生失敗(自動再生ポリシー): 起動はユーザー操作(ボタン)なので再生可。失敗は無音で継続。
- 立ち絵/音声の404: onerror で静かにスキップ(物語は文字で進む)。
