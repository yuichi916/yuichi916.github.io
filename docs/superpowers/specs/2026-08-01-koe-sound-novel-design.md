## 1. 狙い

`seikai.html`（正解の外側／全15話）のエンジンとノウハウを流用しつつ、**まったく別の短編**を作る。
狙いは3つ。

1. **サウンドノベルにしかできないギミックを、短編尺で最大出力する**
2. **人間の制作体制では採算が合わない／物理的に録れないものを、作品の表現そのものとして使う**（AI制作ネイティブ）
3. **起承転結のあるボーイミーツガールとして、どんでん返しで泣かせる**

「AIで安く作った」ではなく「**AIでなければ書けなかった構造**」を成立させることが本作の目標。

## 2. 中核ギミック

本作はフルボイス。主人公も脇役も喋る。
**ヒロインの台詞だけ、作中で一度も声が鳴らない。**

プレイヤーは「喋れない設定だからそういう演出なのだろう」と受け取る。ここに疑いを持たせない。

ギミックは三段構え。

1. **ヒロインだけ無音**（上記）
2. **タイトル画面で一度だけ、誰のものとも知れない少女の声が1フレーズ鳴る**。起動時に聞き流させる
3. **地の文はカナタの声で鳴っている**——とプレイヤーは思っている

3つすべてが終盤で回収される。

## 4. 設定の骨（3つの問いに答える形で確定済み）

### Q. セイレンは何者か

**〈静音器（せいおんき）〉** ——都市の設備。

〈クワイエタス〉は地中の巨大な空洞の上に建つ都市で、音が共振すると地盤が崩れる。だから建設時、都市は最下層に「音を吸って溜め込み続ける器」を据えた。
人の形をしているのは、**人は、人の形にしか声を預けないから**。

彼女に声がないのは、**吸う機能しか持たされていないから**。器に出力はいらない。

### Q. なぜ音を吸うのか

悪意ではなく**仕事**だから。街が立っていられるように、千年間そうしてきた。街の住人は誰も知らない。

**そして今、器は満杯に近い。** だから最近になって音が消える速度が上がっている——溢れる前に、より強く吸って押し込もうとしている。

この設定が探索パートの土台になる：**カナタが廃墟で拾っている「音」は、満杯の器から漏れ出したもの**。だから最近やたらと拾える。街の人々は、自分が失った声を、それと知らずに買い戻している。

彼女に記憶がないのは、器が定期的に初期化されるから（溜めた音は放っておくと人格を形成してしまう）。カナタが出会ったのは初期化直後の彼女。

### Q. なぜ声を与えると彼女は消えるのか

**吸うと吐くは、同じ穴を使う。片方を開ければ、片方は閉じる。**

声を与える＝器に出力を与える＝もう吸えなくなる。溜めた音は全部、街に還る。
しかし**彼女の人格は、溜めた音でできている**。奪った音が形になったものが、彼女という存在。だから返せば、彼女は消える。

## 5. 起承転結

### 起（約5分）
カナタは今日も廃墟で音を採る。放送塔の最下層で、声の出ない少女セイレンに出会う。彼女は自分が誰かも、なぜここにいるかも分からない。カナタは「きみの声を作ってやる」と言ってしまう。

**伏線**: カナタが冗談まじりに「聞こえないなら、俺の声、録っといてやるよ」と自分の声を彼女に吹き込む。

### 承（約10分）
街の四箇所（市場／水路／旧劇場／塔）で「声の素材」を採取する探索パート。母音、息、笑い、泣き声。集めた音はプレイヤーの手元に実際に貯まる。

各所の構成は **主素材1つ ＋ 記憶片5つ** ＝ 1か所あたり6枚、4か所で **24枚**。

- **主素材**（`{pickup:..., main:1}`）：必ず取得する。合成度が1段階上がる
- **記憶片**（`{pickup:...}`）：`explore` のパノラマ内に隠れており、見つけた分だけ集まる。合成度は上がらないが、転パートのモンタージュの密度になる

採取のたびに合成度が上がり、**途中経過の声を試聴できる**（`{tryvoice:1}`）。
並行して街から音が消える速度が上がる。二人の距離が縮まる。

**カナタ側の必然**: 彼の母は数年前に声を失った。彼が音の拾い屋になったのは、母の声を探すため。

### 転（約7分）
採取した音が、すべてかつて街の誰かが失った声だと判明する。**そのうち1つが母の声だった。**
〈静音器〉の正体はセイレン自身——彼女は音を吸い続ける存在で、それを知らずにいた。彼女は逃げる。
集めた記憶絵が一気に流れるモンタージュ（`{montage:1}`）で、コレクションが罪状の一覧に反転する。

カナタは選ぶ（`choose`）。**結末は合流させ、演出差分のみとする**（短編で分岐エンドは作らない）。

### 結（約5分）
声が完成し、鳴る（`{finalvoice:1}`）。彼女が生まれて初めて発した言葉——**この台詞はプレイヤーの採取順によって4パターンある**（最初に主素材を取った場所で決まる）。
声を得たセイレンは〈静音器〉ではなくなり、吸っていた音がすべて街に還る。母の声も還る。

**最後の反転**——返しきったはずなのに、たった一つだけ残った音がある。**カナタの声**。
なぜ返せないか。それは奪ったものではなく、**彼が自分の意思であげたものだから**。奪った音は返せる。もらったものは返せない。

だから彼女は消えなかった。彼の声ひとつを持って残った。
**そしてこの物語全体は、その後に彼女が、彼の声を使って語り直した回想である。** 地の文がカナタの声で鳴っていたのは、それが彼女に残された唯一の音だから。プレイヤーはずっと、彼女の再生を聴いていた。

### 最終シーン
音が還ったとき、街の記録から彼女という存在は消えた。**カナタは彼女を覚えていない。**
彼女は語り終える。彼の声を使い切り、手放す。
残響区の路地で、音の拾い屋の少年とすれ違う。彼は彼女を知らない。
彼女は自分の声で言う——「——おはよう」
彼が、振り返る。

**これが起動時にタイトル画面で鳴っていた声である**（同一の音声ファイル `title-koe.mp3` を再生する）。最初に聞き流した一言は、物語の最後の一言だった。

なお、結パートで鳴る「完成した声」（4パターン）とこの最終シーンの声は別物である。前者は彼女が最初に発した言葉、後者は彼女が最後に言う言葉。タイトル画面の回収は**最終シーンでのみ**起きる。

### 2周目
地の文は最初からセイレンの声で鳴る。テキストは一文字も変わらない。
彼女はもうカナタの声を持っていない。それでも語り直している——自分の声で。

## 7. AI制作ネイティブの表現（6項目）

人間の制作体制では採算が合わない／物理的に録れないが、AIエージェント制作なら成立する要素を、物語の必然として使う。

### 7-1. 声の「合成度」を実音で聴かせる（本作の目玉）

承パートの採取ごとに途中経過を試聴できる。

| 段階 | 採取数 | 鳴るもの |
|---|---|---|
| 0% | 0 | ノイズと呼気だけ |
| 25% | 1 | 音素は出るが言葉にならない |
| 50% | 2 | 単語の断片が混じる |
| 75% | 3 | 片言。かろうじて意味が通る |
| 100% | 4 | 完全な声 |

**声優には録れない**。「壊れ方が連続的に回復していく5段階」を人間の演技で作るのは不可能。AI合成音＋DSPだから成立する。
「声が組み上がっていく」がテキストの説明ではなく耳で分かる。

### 7-2. 拾った音の「記憶」をSD一枚絵で挿す（物量が表現になる）

音を1つ拾うたび、その音がかつて誰のものだったかの情景が1.4秒フラッシュする。reForge で24枚生成。
人間制作なら一枚絵24枚は予算的に不可能で、通常はCG3〜4枚に切り詰める。ここを24枚にできること自体が、**転パートのモンタージュ**を成立させる。プレイヤーが自分で集めた絵が、そのまま罪状の一覧に反転する。

### 7-3. セイレンの表情差分を24種（無音の必然）

彼女は声が鳴らない。だから**表情と身振りが彼女の唯一の言語**になる。立ち絵差分が多いほど物語の解像度が上がる、という構造的必然がある。
人間制作の立ち絵差分は5〜8種が相場。24種はAI制作の直接的な優位であり、かつ作品の中心設定がそれを要求している。
（カナタとトキは声があるので差分は4種ずつ＝リソース配分も物語と一致）

### 7-4. 2周目は「同じ字幕・違う声」

地の文をカナタ声／セイレン声の2バージョン生成する。声優2人に全編を録り直させるのと等価な作業で、AIだから回せる。

### 7-5. 完成する声はプレイヤーごとに違う

採取した音の組み合わせ4通りに対して、完成ボイスのテイクを4種類用意する。「あなたが作った声」という個別性。

### 7-6. 主題と制作手法の一致

少年が作中でやっていること——**存在しない声を、集めた素材から合成する**——は、この作品の制作者がやっていることと同じ。
エンドクレジットに一行だけ「セイレンの声は合成されたものです」と置く。説明はしない。

### 8-3. 「セイレンだけ無音」の実装（既定と例外を逆にする）

```js

if(b.say==='ren'){ if(b.v) playVoice('ren', b.text); else stopVoice(); }
else if(b.say==='kanata'||b.say==='toki'){ playVoice(b.say, b.text); }
else if(b.say==='narr'){ playVoice(st.narr||'kanata', b.text, 'narr'); }
```

地の文のファイル名は話者名をハッシュに含めず、サフィックスで分ける。

```js
function voiceFile(who, text, kind){
  if(kind==='narr') return A+'voice/n'+keyOf(text)+(who==='ren'?'_r':'_k')+'.mp3';
  return A+'voice/v'+keyOf(who+'|'+text)+'.mp3';

```

これで地の文の台本を1文字直しても2系統が同時にずれる（片方だけ生き残って気づかない、が起きない）。

**セイレンの台詞の表示形式**：名前欄には「セイレン」ではなく **`—`（ダッシュ）** を出し、テキストは他キャラより一段小さく、字送りをやや遅くする。声がないことを「音の欠落」ではなく「別の話し方」として提示するための処理。結パートで初めて声が鳴るとき、名前欄が `—` から「セイレン」に変わる。

### 8-4. タイトル画面の声（autoplay制限への対処）

「起動時に1回だけ少女の声が鳴る」が autoplay ブロックで素通りされると仕掛けが全部死ぬ。導線で解決する。

1. 起動 → 真っ黒な画面に「画面をタップ」だけ
2. タップ（＝ユーザージェスチャ取得）→ その瞬間に `voice/title-koe.mp3` を再生
3. 声が鳴り終わってからタイトルロゴとメニューがフェードイン

この1本だけ `cfg.voice` の下限を20%に張る。

### 8-5. ボイスパイプライン（ElevenLabs v3）

声は3種——カナタ／トキ／セイレン。地の文はカナタ声版とセイレン声版の2本立て。

内訳：

| 系統 | 本数 | 備考 |
|---|---|---|
| カナタ（会話） | 120 | `v<hash>.mp3` |
| トキ（会話） | 40 | `v<hash>.mp3` |
| 地の文・カナタ声 | 50 | `n<hash>_k.mp3` |
| 地の文・セイレン声 | 50 | `n<hash>_r.mp3`（同一テキスト） |
| セイレン（結パート以降の台詞） | 20 | `v<hash>.mp3`。**`v:1` 指定ビートからのみ再生** |
| 完成声 4パターン | 4 | `{finalvoice:1}` 用 |
| 段階合成 4パターン×5段階 | 20 | うち100%段階は上記4本と同一なので実生成は16 |
| タイトル声 | 1 | `title-koe.mp3`。**固定1本**（最終シーンの「——おはよう」と同一ファイル） |
| **合計** | **約281** | |

`sound-novel-production` で潰した事故を最初から避ける。

- **演技タグは短いオーディオタグ1個まで**（`[whispers]` `[sad]` 等）。カンマ区切りの説明列は読み上げられる
- **漢字の読み違いは文字比較で検出できない**ので、TTSへ送る文字列だけ仮名に置換。`空`/`何`/`人` 等は `GUARD` で別読み語を退避してから戻す。ルビ表記 `静音器(せいおんき)` は読み仮名だけに畳む
- **QA**: faster-whisper で書き起こし。`suppress_tokens` に漢字トークンを全部入れて仮名を強制（`initial_prompt` だけでは29%しか仮名にならない）
- **異常検出**は比率ではなく話者別の回帰残差。`dur ≈ a + b×字数` を頑健フィットし、残差>2.5秒＝余計な音、尺62%未満＋一致率62%未満＝欠落、の二段
- **棚卸し**: 台本から全台詞を抽出 → 期待ファイル名を算出 → **欠落0／孤児0**。地の文は `_k` `_r` の対で揃っているかも検査

### 8-6. 声の合成度5段階の生成

完成ボイス1本から、Python（librosa / soundfile / scipy）で機械導出する。

| 段階 | 処理 |
|---|---|
| 0% | スペクトル包絡を残しノイズ励振に差し替え（無声化）＋強LPF。呼気だけになる |
| 25% | グラニュラー分解（粒25ms）して順序をシャッフル。音素は出るが言葉にならない |
| 50% | 有声区間の50%をノイズでゲート。単語の断片だけ通る |
| 75% | 区間欠落15%＋ピッチ揺らぎ±40cent＋軽いビットクラッシュ。片言 |
| 100% | 無加工 |

4パターン × 5段階 ＝ 20本。

### 8-7. SD画像生成（reForge）

**立ち絵32枚**（セイレン24／カナタ4／トキ4）

- 同一 seed・同一プロンプト骨格で、表情句だけ差し替え。ADetailer で顔を安定させる
- LoRA は CivitAI の正式ファイル名のままリネームせず使用
- 「anime style, flat color」は入れない（薄線フラット化して他キャラと画風が乖離する）
- 背景透過は rembg → `scipy.ndimage.binary_fill_holes` ＋内側3px erosion で穴を補修

**記憶絵24枚**（1.4秒フラッシュ）

「かつて誰かがその音を持っていた情景」。統一プロンプト系統＋固定 LoRA、彩度を落として時間経過を出す。

QCは腕の本数を肩から数える／端を拡大／髪の別人顔をチェックリストにして ALL CLEAN まで再生成する。
**画風の統一が最重要**。24枚が別々のAI画像の寄せ集めに見えた瞬間にモンタージュが死ぬので、seed とプロンプト骨格の固定を先に確立してから量産に入る。

### 8-8. 3D背景（Blender）

## 9. 制作順序

### フェーズ0：プリフライト（先にリスクを潰す）

1. **声の段階合成DSPのプロトタイプ**を1台詞で作る ← **最大の技術リスク**。5段階を並べて聴き、「壊れた声が組み上がっていく」と聞こえるか判定。ノイズにしか聞こえないなら、DSPではなく「音素を実際に欠落させた台詞をElevenLabsで直接生成する」方式に切り替える
2. ElevenLabs で声3種のキャスティング（各3候補×2台詞で選定）
3. BGM 10曲を実試聴で確定、mp3化、キー命名
4. reForge 起動確認・LoRA 実在確認・立ち絵1枚ドライラン
5. Blender で Future Slums を1ロケだけ通しレンダ（時間計測）
6. ディスク空き確認

### フェーズ1：脚本

`novel-writing-craft` を使って全編執筆。台本は `assets\koe\koe-ep1.js` に素のJSデータとして書き、エンジンには触らせない。

**特殊な縛り**——地の文は、カナタの声で読んでも、セイレンの声で読んでも成立しなければならない。
1周目は「少年の心内」として、2周目は「彼女が彼の声を借りて語った回想」として読める文章にする。「俺は」で始まる一人称は使えるが、彼女が語っていると分かった瞬間に嘘になる文は書けない。**地の文の全行に対する二重読みチェック表**を作る。

同時に作るもの：
- 伏線埋め込み表（起動時の声／「俺の声、録っといてやるよ」／漏れ出す音／母の声／人の形の理由）
- 採取4か所 × 記憶絵24枚の対応表
- 設定説明台詞の合計秒数（90秒以内）

### フェーズ2：エンジン

`seikai.html` から骨格を移植して `koe.html` を作り、新6命令を実装。

## 10. 検証計画

### 本作固有の必須チェック

| 検証 | 方法 | 合格条件 |
|---|---|---|
| **セイレンの無音が守られているか** | Playwright でネットワークログを取り、`say:'ren'` のビート通過時の `voice/` リクエストを数える | `v:1` 指定ビート以外で **0件** |
| **地の文2系統が対で揃っているか** | 棚卸しスクリプトで `n<hash>_k.mp3` と `n<hash>_r.mp3` の存在を突合 | 片側欠けが **0件** |
| **タイトルの声が確実に鳴るか** | 初回タップ後の `title-koe.mp3` の `currentTime` を実測 | 再生完了を確認 |

### 既定の検証

- `node --check`（インラインscript抽出。importmap JSONのFAILは正常）
- **commit前の重複宣言チェック**: `python C:/tmp/check_dup_const.py koe.html` が exit 0
- BGMキー実在 assert
- 立ち絵位置キーの定義表突合
- E2E 通し（Playwright／swiftshader／ローカルHTTP。**選択肢クリックはJSの `.click()`**）
- セーブ往復
- 2周目で地の文がセイレン声になること

### 人手の確認

最後に2周プレイする。1周目で仕掛けに気づかないか、2周目で意味が反転するか——これは自動テストでは測れない。

## 11. リスクと対処

| リスク | 対処 |
|---|---|
| 段階合成がノイズにしか聞こえない | フェーズ0で判定。ダメならElevenLabs直接生成方式へ |
| 地の文の二重読みが破綻する | 脚本フェーズで全行チェック表。破綻行は書き直す |
| 記憶絵24枚の画風が割れる | スタイルブック先行。24枚並べて判定 |
| 無音が「手抜き」に見える | 起パートで「彼女は声が出ない」を正面から扱い、演出意図として納得させる |
| 20分に収まらない | 脚本段階で文字数から尺を概算（`dur ≈ a + b×字数` の係数を流用） |
| HTMLへのパッチでJS文字列が壊れる | heredoc を使わず、必ず Write ツールでスクリプトを書いてから実行する |
