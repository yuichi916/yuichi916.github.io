# AIエージェントのプロになる教科書【2026年9月版】

Claude Code、Codex、Cowork。AIエージェントで仕事の成果物をつくるときの「こんなはずでは」を、先回りで潰すための連載の入口です。

---

## 「こんなはずでは」に、覚えはありますか

- 「いい感じに」と頼んだら、思っていたのと違うものが返ってきた
- 一部だけ直してほしかったのに、良かった所まで変わってしまった
- 「完了しました」と言われたのに、動いていなかった
- ほぼ合っている。でも、どこかが違う
- 長くやり取りしていたら、最初に言ったルールを忘れられていた
- 資料を出したら「これ、AIで作ったでしょ」と言われた
- 定額のつもりだったのに、上限で止まった

どれも、あなただけではありません。

エンジニア437人に聞いた調査では、AIへの不満の1位が「意図と異なるものが生成される」で、54.9%でした。世界の開発者を対象にした Stack Overflow の2025年の調査では、1位が「ほぼ正しいが、正しくない」で66%。画像や動画を生成AIで作っている人の調査では、「一部だけ直したいのに、良い部分も消える」が44.2%で1位です。企業の購買担当者の9割は、「AIで作った資料」を見抜いた経験があると答えています。

一つでも覚えがあれば、この連載はあなたに向けて書いています。

---

## プロとそうでない人の差は、プロンプトではない

この連載でいう「プロ」は、こういう人です。

**期待どおりの成果物を、毎回、事故なく出せる人。**

AIエージェントは、この1年で見違えるほど賢くなりました。それでも、上の「こんなはずでは」は減っていません。

AIエージェントが失敗した1,642件の記録を分類した研究（MAST）があります。失敗の原因でいちばん多かったのは「仕様」の問題で41.8%、次が「確認と終わらせ方」の問題で21.3%でした。

AIの頭の良さの問題ではありません。**渡し方と、受け取り方の問題**です。

私はAIエージェントが仕事ごとにどこまでできるかを、326の仕事について調べて地図にしています（[AIエージェント能力アトラス](https://yuichi916.github.io/ai-map.html)）。そこでも同じ形が出ました。テストコードを書く力は「専門家並み」なのに、自分が書いたコードの正しさを確かめる力は「補助」どまり。作る力と、確かめる力に、2段の差があります。

だから、モデルが新しくなるのを待っていても、「こんなはずでは」は消えません。消せるのは、使う側です。

---

## 私も、ひと通り踏みました

私は、AIエージェント（主に Claude Code）と一緒に、サウンドノベルや3Dの絵本、音楽の地図など、16の作品を作って公開してきました。その間に、上のあるあるは、ほとんど全部踏んでいます。

- 3Dの背景を頼んで、「背景が真っ黒」としか言えず、同じ場所を2日半で6回作り直した
- 改稿したら、音声161本が数週間、無音のまま公開されていた。エラーは一度も出なかった
- 翻訳のファイルを公開し忘れて、多言語版が全部日本語で表示された。手元のテストは全部通っていた
- 出来の採点もAIにやらせたら、その採点が甘いのか辛いのか判定できなかった

今は、少し違います。

先日、深夜に Claude Opus 5.5 の発表を読んで、約1時間後には紹介動画をXに公開していました。私が打った指示は2つだけです。最終の文面を読まずに「投稿して」と打ちましたが、数字の誤りは公開前に6件止まっていました。止めたのは、事実の確認だけを任せた別のエージェントです。

特別な才能はいりませんでした。変えたのは、渡し方と受け取り方です。この連載は、その変え方を1回に1つずつ書いていきます。

### この1か月の大きな変化

- **Claude Opus 5.5（9月22日）**：大半の作業で上位モデルの Fable 5.1 並み。前の Opus 5 より約4割安く動き（Anthropic の試算）、出力は3割以上速い。文章は、大事なことから先に書くようになりました
- **Claude のチャットと Cowork が一つに（9月16日）**：同じ会話の中で、文書やスライドまで仕上げられるようになりました <!-- 要確認 -->
- **OpenAI は GPT-6 の世代へ（9月）**：成果物を仕上げる ChatGPT Work と、Codex の側で使えます <!-- 要確認 -->

各社の向かう先は同じです。**AIに「聞く」から、AIに「成果物を任せる」へ。**任せる量が増えるほど、渡し方と受け取り方の差が、そのまま成果物の差になります。

### できること、まだできないこと

能力の地図から、仕事で使う人に関係の深いものを抜き出しました。0〜5の6段階で、専門家と比べてどこまで来ているかを示しています。

| 仕事 | 段階（2026年9月） |
|---|---|
| ブログや記事を書く | 4 専門家並み |
| プレゼン資料・スライドを作る | 4 専門家並み |
| 資料を横断して調べ、まとめる | 4 専門家並み |
| ナレーション・読み上げ | 5 専門家超え |
| 本番品質のWebアプリを作る | 3 人が確認すれば出せる |
| 自分の原稿を評価して直す | 3 人が確認すれば出せる |
| 自分のコードの正しさを確かめる | 2 補助 |
| 原因不明の不具合の切り分け | 2 補助 |
| 複数のアプリをまたぐ定型業務 | 2 補助（最良のエージェントでも、自分で最後までやり切れるのは3割ほど） |

地図の結論は、1行にするとこうでした。

**AIは「答え合わせができる仕事」から順に、できるようになっている。**

作るのは速い。自分で答え合わせをするのは苦手。だから、答え合わせの手段を渡す人ほど、AIに大きな仕事を任せられます。

## プロの原則10

連載の10回を、1行ずつにしたものです。今日から使えます。

1. **作らせる前に、決めることを出させる**。「この作業で私が決めないといけないことを5つ挙げて」から始める（#01）
2. **一部を直すときは、変える所と変えない所を両方言う**（#02）
3. **同じことを2回直して直らなければ、会話を捨てて、頼み方を変えてやり直す**（#02）
4. **覚えさせたいことは、会話ではなくファイルに書く**（#03）
5. **「完了しました」は、報告ではなく確認の結果で受け取る**（#04）
6. **数字と出典は、原文と照合できるものだけ使わせる**（#05）
7. **「AIっぽさ」は、平均に寄った結果。外したい定番を先に名指しする**（#06）
8. **消されて困るものは、任せる前に守る**（#07）
9. **上限は二重（数時間の枠と週の枠）。重い仕事と軽い仕事でモデルを分ける**（#08）
10. **良し悪しが分からない分野では、評価せずに、並べて選ぶ**（#09）

そして、**同じことを3回言ったら、仕組みにする**（#10）。

## この連載について

**毎週火曜、全10回**。各回、1つの「こんなはずでは」だけを扱います。

各回の前半は無料です。何が起きていて、なぜ起きるのか、どう変わるのかまで読めます。後半は有料で、そのまま使える依頼文、実例、チェックリストを置きます。

全10回をまとめたマガジンも用意します。あとから公開する回も、追加料金なしで読めます。価格は回が増えるごとに上げるので、早く買った人ほど安くなります。

**書かないこと**

- AIで稼ぐ方法
- ツールの機能を並べただけの紹介。機能は毎月変わるので、本文には「変わらない原則と判断」を書きます。モデル名や料金は、各回の最後の「最新メモ」に分けて、日付を入れて更新します

**向いている人**：Claude Code、Codex、Cowork、ChatGPT などで、仕事の成果物（資料、文章、サイト、ツール）を作っている人、これから作る人。エンジニアでなくても読めるように書きます。

この「教科書」は、毎月書き直します。次の改訂は10月です。
