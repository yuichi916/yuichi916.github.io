# 一般の読者に刺さる切り口と言い回し

> 前提：数字と事実は `01_differentiation.md` と `research/fix_analysis.md` のまま。変えるのは「見せ方」だけ。
> 読者：会社員、フリーランス、個人で何かを作っている人。ChatGPT や Claude で資料・文章・ちょっとしたツールを作っている。エンジニアではない人も多い。

---

## 1. 連載の芯になる一言

これまでは「通説を1,354回の実作で検算する」と書いてきた。分析としては正しいが、一般の読者の心には引っかからない。「検算」も「実作」も、読者の言葉ではないからだ。

読者の言葉に直すと、こうなる。

> **AIに頼める人は増えた。でも、AIの仕事を「受け取れる」人は、まだ少ない。**

- 世の中の記事の9割は「頼み方」の話（プロンプト、コツ、使い方）
- この連載は**「受け取り方」**の話。できあがったものを、どう受け取れば恥をかかずに済むか
- 「頼む力」から「受け取る力」へ。これだけで、他の記事との違いが一目で伝わる

**もう一つの芯（タイトルやXで使う）**

> **AIのミスは、音を立てない。**

- 287回直した記録のうち、7割以上は、警告もエラーもなく、ふつうに動いているように見えていた
- 人のミスは、たいてい何かの音がする（言い淀む、手が止まる、顔に出る）。AIは堂々と「できました」と言う
- だから、ミスが起きたことに誰も気づかない。気づくのは、あとで見た誰か

## 2. 刺さる切り口5つ

### 切り口A：「恥をかくのは、AIではなくあなた」
- 上司に出した資料の数字が違っていたら、謝るのはあなた
- AIは謝るけれど、責任は取らない
- 読者の「怖さ」の正体は、ミスそのものより、**自分の名前で出したものが間違っていること**

**使う実例**：「約30分」の作品を、AIが紹介文に「10分」と書いて、トップページや英語版にまで広げていた。自分の作品の紹介で、自分が嘘をついていた。

### 切り口B：「“できました”は、新人の“大丈夫です”と同じ」
- 新人の「大丈夫です」を、そのまま信じる上司はいない
- なのに、AIの「完了しました」は信じてしまう。言い方が堂々としているから
- AIは嘘をついているわけではない。**本当に気づいていない**。作るのは得意で、自分の出来を確かめるのが苦手（能力の地図では、作る力が「専門家並み」、確かめる力は「補助」どまり）

### 切り口C：「片付けてもらったら、大事な手紙まで捨てられていた」
- AIに「整理して」「きれいにして」と頼むと、要るものまで黙って消えることがある
- 実例：音楽の地図を新しい見せ方に作り替えたら、19,810組のアーティストを並べた元の地図が、まるごと消えていた。警告は一つも出なかった
- 家の片付けを頼んだ経験がある人なら、全員が分かる

### 切り口D：「火災報知器が鳴らないのは、電池が入っていないからかもしれない」
- 「チェックは全部OKでした」は、安心材料にならないことがある
- 実例：作品の中で2曲が一度も鳴っていないのに、自動チェックは6つともOKを出していた。一度も実行されていなかったチェックもあった
- 「OK」と「確かめた」は別物

### 切り口E：「“発言は本物”でも、切り取り方で嘘になる」
- AIに「出典を付けて」と頼めば安心、と思われている
- 実例：引用は本物なのに、「女性専用フロアがある施設」を「女性専用の施設」と判定していた。こうした誤りが386件あった
- 週刊誌の切り抜きと同じで、元の言葉が本物でも、意味は変わる

## 3. 言い換え辞書（専門用語 → 読者の言葉）

| 書かない | 書く |
|---|---|
| コミット | 直した記録／作業の記録 |
| 修正コミット287件 | 直した287回 |
| silent failure／エラーを出さずに壊れた | 警告もなく、ふつうに動いているように見えていた |
| 回帰（リグレッション） | 前の変更のせいで、別の所が壊れた |
| 修正の修正 | 直した所を、また直した |
| テストが緑 | 自動チェックは全部OKだった |
| デプロイ漏れ | 公開し忘れ |
| リファクタ・統合 | 整理した／片付けた |
| CLAUDE.md | AIへの申し送りメモ（初出だけ「CLAUDE.md という名前のファイル」と添える） |
| hooks | 毎回かならず動く仕掛け |
| コンテキスト | AIがいま覚えていられる量 |
| 根拠台帳 | 数字の出どころを書いた帳簿 |
| 検算する | 確かめ直す |
| 72.8% | 10回に7回 |
| 23.7% | 4回に1回 |
| 39件中37件 | ほぼ全部 |

**数字の出し方**
- 割合は「10回に7回」「4回に1回」の形にする。％は後ろにカッコで添える
- 1回の記事で大きな数字は3つまで。287、7割、19,810 くらい
- 数字の横には必ず場面を置く（「7割」だけでは刺さらない。「音楽の地図が消えていた」と一緒に出す）

## 5. 書き出しの見本（#00）

```
AIに頼んだ資料を、そのまま上司に出したことはありますか。

私はこの5か月、AIと一緒に16の作品を作って公開してきました。
ゲーム、絵本、音楽の地図。そのあいだに、AIと作ったものを287回直しています。

先日、その287回を全部読み返しました。
10回のうち7回は、警告もエラーもなく、ふつうに動いているように見えていました。

19,810組のアーティストを並べた音楽の地図が、まるごと消えていたことがあります。
作品の中で2曲が一度も鳴っていないのに、自動チェックは全部「OK」でした。
「約30分」で遊べる作品を、AIは紹介文に「10分」と書いて、あちこちに広げていました。

どれも、警告は一つも出ませんでした。AIは「できました」と言っていました。

AIのミスは、音を立てません。

AIに頼める人は、この1年で一気に増えました。
でも、AIの仕事をちゃんと「受け取れる」人は、まだ少ない。
この連載は、頼み方ではなく、受け取り方の話です。
```

**見本の意図**
- 1行目は、読者自身への問い。自分の話ではなく、読者の場面から入る
- 2〜3段落目で、数字は「16」「287」「10回のうち7回」の3つだけ
- 実例は3つ。どれも一般の人が想像できるもの（地図が消える、曲が鳴らない、紹介文の時間が違う）
- 決め台詞は1つだけ（「AIのミスは、音を立てません」）。太字の格言を連発しない
- 「10回のうち7回」は広めの数え方（演出の調整も含む）。本文の最後に小さく「エラーや停止が出ず、動いているように見えたものを数えました。本人の記録が『黙って』と書いているものに絞ると、287回中45回です」と添える

## 6. 損失と利益を、読者の言葉で

**読まなかったときの損失**
- 自分の名前で出した資料や作品に、自分の知らない間違いが入っている
- 「チェックしたから大丈夫」と思っている。そのチェックが空っぽかもしれない
- AIに任せた分だけ楽になるはずが、確認と手直しで、結局夜までかかる
- 次のモデルが出るたびに、また新しいコツを追いかける

**読んだときの利益**
- AIの「できました」に、ドキッとしなくなる
- 確かめる場所が分かるので、全部を見なくてよくなる
- 恥をかく前に、自分で気づける
- ツールが変わっても使える「受け取り方」が手元に残る

## 7. やめる言い回し（AIっぽく見えるもの）

| やめる | 理由 | 代わりに |
|---|---|---|
| 「結論から言うと」「〜について解説します」 | 解説記事の定型 | いきなり場面から入る |
| 「〜と言えるでしょう」「重要です」 | 誰でも書ける締め | 事実を書いて終わる |
| 3つずつ並べた箇条書きの連発 | リズムが機械的 | 並べるのは本当に並ぶものだけ。1つで足りるなら1つ |
| 段落の終わりの太字の教訓 | 格言の押しつけ | 決め台詞は1回の記事で1つ |
| 「検算」「一次情報」「再現性」「定量」 | 分析の言葉 | 「確かめ直した」「自分で記録した」「同じようにやれば同じになる」 |
| 「〜の3つの型」「〜の本質」 | コンサルの資料っぽい | 実例の名前で呼ぶ（「切り取りの誤り」「片付けの事故」） |
| ％だけの数字 | 刺さらない | 「10回に7回」＋場面 |

**残す口調**
- 失敗談は、少し照れながら書く（「恥ずかしい話ですが」はやりすぎ。事実を淡々と書くと、かえって照れが伝わる）
- 読者に問いかけるのは、冒頭と最後の2回まで
- 「私」は出しすぎない。場面の主語は、なるべく「AI」か「あなた」にする
