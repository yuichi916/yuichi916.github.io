## 一言で

**AIエージェントの「通説」を、5か月・1,354回の実作で検算した教科書。**

他の記事は「こうすると良い」と主張する。この連載は「実際に作って、直した記録で確かめたら、こうだった」を見せる。

## 1. 読者の興味 — 何に惹かれて読むのか

### 読者の頭の中にある問い

AIエージェントで成果物を作っている人は、コツを知らないわけではない。むしろ知りすぎている。

- 「CLAUDE.md にルールを書こう」と「CLAUDE.md は短くしろ」
- 「AIにレビューさせよう」と「AIの自己評価は甘い」
- 「テストを書かせれば大丈夫」と「テストを握り潰す」

**どれが本当に効くのか、分からない。**読者の本当の問いは「次のコツは何か」ではない。「どれを信じればいいのか」と「自分も同じ失敗をするのか」の2つ。

競合を見ても、この問いに答えている記事はない。集めた実在タイトル90件の内訳はこうだった。

| 種類 | 件数 | 読者の問いに答えているか |
|---|---|---|
| 使い方・完全ガイド | 34 | 機能は分かる。どれが効くかは分からない |
| Tips・〇選・習慣 | 22 | コツは増える。どれを信じるかは分からない |
| プロンプト・テンプレ集 | 15 | 道具は増える。効くかは分からない |
| 体験記（1ヶ月使ってみた） | 14 | 一人の印象。数えていない |
| 稼ぐ・副業 | 9 | 別の問い |
| 検証・比較 | 5 | 乗り換えの感想やプロンプトの比較。実際の制作記録で確かめたものは0件 |

### 目を止める入口：実物の「こんなはずでは」

このリポジトリの修正履歴には、読者が「自分にも起きそう」と思う実物が残っている。どれも、エラーは出ていない。

- **音楽の地図が、黙って消えていた。**別の図に作り替えたとき、19,810組のアーティストを並べた元の地図とデータが、一緒に外されていた。画面は普通に動いていた（2026-06-15、f3c5cce9）
- **引用元のページに無い「事実」が461件あった。**取り込んだ引用を実際のページと照合し直すと、9.1%が見つからなかった（2026-09-10、41d5c67b）
- **案内の帯が、いちばん人の来る作品の入口を塞いでいた。**しかも、最初の直し方も効いていなかった（2026-08-26、adc1c251）
- **音声161本が、数週間無音だった**
- **最終の文面を読まずに「投稿して」と打ったが、誤りが公開前に6件止まっていた**

興味の順番は、「うわ、ありそう」→「自分の成果物は大丈夫か」→「じゃあ何を信じればいい？」。この順で入口を作る。

## 2. 読まなかったときの損失 — 放置コスト

煽らず、読者がもう払っているコストを言葉にする。

**① 効かない対策に、時間を使い続ける**
CLAUDE.md を長く書き足しても、守られない。AIに採点させても、その採点が甘いのか辛いのか判定できない。どちらも、やっている本人は「対策した」と思っている。

**② 気づかない失敗が、そのまま外に出る**
上の実物は、どれもエラーを出さなかった。見つけるのは、あなたではなく、読者や顧客や上司になる。成果物の出来より先に、信用が減る。

**③ 速くなった気がするまま、遅くなる**
経験のある開発者が「20%速くなった」と感じていたのに、実測では19%遅かったという研究がある（METR、2025年）。体感では気づけない。

**④ モデルが出るたびに、学び直しになる**
使い方の記事は、次のモデルで古くなる。2026年9月だけでも、Fable 5.1（9/1）、チャットと Cowork の統合（9/16）、Opus 5.5（9/22）と続いた。

一言にすると、**「対策しているつもりで、損をしている状態」が続く。**

## 3. 読んだときの利益 — 読後の変化

| 読む前 | 読んだ後 |
|---|---|
| コツを片っ端から試す | どの通説が効き、どれが効かないかを知って、対策を絞れる |
| 「完了しました」を信じるか、全部目で見るか | 何が機械で止まり、何が止まらないかを知って、目を使う場所を絞れる |
| 黙って壊れたものを、読者に見つけられる | 自分の成果物で起きやすい「黙って壊れる形」を、公開前に止める手順と道具が手元にある |
| どこまで任せていいか分からない | 326の仕事の地図で、自分の仕事の段階を見て決められる |
| 新しいモデルが出るたびに学び直す | 変わらない原則は本文に、変わる情報は月1回更新の「最新メモ」に分かれている |

**約束するのは「失敗しない」ではない。**「同じ形の失敗を、公開前に止められる」こと。

## 4. なぜこの連載でないといけないのか — 独自性の証拠

| | よくある記事 | この連載 |
|---|---|---|
| 根拠 | 書き手の印象。長くても1ヶ月の体験 | 5か月・1,354コミット（うち約775件がClaudeとの共同）、直したコミット284件、公開済みの16作品 |
| 形 | 「こうすると良い」という主張 | 「通説 → 記録で検算 → 判定（正しい／半分／誤り）→ 代わりにやること」 |
| 確かめられるか | 確かめられない | 作品を開ける。研究ノート、能力の地図、直す前と後が見られる |
| 範囲 | エンジニアの効率化か、初心者の入門 | 専門外（3D、音、音楽、UI、物語）まで含めて、成果物を最後まで出す |
| 鮮度 | 書いた時点で止まる | 326の仕事の地図と一緒に、月1回更新する |
| 稼ぐ話 | 多い | 書かない |

**書き手にしかない材料**

- このリポジトリの全履歴：何を作り、何が壊れ、どう直したかが全部残っている
- AIエージェント能力アトラス：326の仕事、6段階、2022→2030年、根拠リンクつき。毎月更新
- 研究ノート10本：通説を公開コードで検算した「Xの測り方」を含む
- 公開済みの16作品：読者が自分で開ける

直したコミット284件の分類（何が壊れたか／エラーを出さずに壊れていたか／誰が気づいたか／前のAIの変更が原因か）が終わったら、ここに数字を足す。**「284件のうち〇%は、エラーを出さずに壊れていた」は、他の誰も書けない一文になる。**

## 5. 連載への反映

### 各回の型

```
通説（よく言われていること）
→ 私の記録で検算すると（実物と数字）
→ 判定：正しい／半分正しい／間違い
→ 代わりにやること（依頼文・規約・道具）
```

タイトルの形（先頭25字にツール名か通説を入れる）

- 「CLAUDE.mdに書けば守る」は半分うそだった｜1,354回の実作で検算
- Claude Codeに「引用を付けて」と頼んでも、事実は正しくならない

### 通説と各回の対応（判定は仮。284件の分類で確かめる）

| 回 | 通説 | 仮の判定 | 手元の根拠 |
|---|---|---|---|
| #01 | 丁寧に指示すれば、思いどおりになる | 半分 | 決めることを知らないと、丁寧に書けない（3Dの背景を6回） |
| #02 | 「ここだけ直して」と頼めば直る | 要検算 | 直したコミットの修正の修正（帯の例） |
| #03 | CLAUDE.md に書けば守る | 半分 | 公式も「助言」扱い。必ずやらせたいことは hooks に書く |
| #04 | 最後に人間が確認すれば大丈夫 | 間違い | 161本、帯、音楽の地図。どれもエラーが出なかった |
| #05 | 引用や出典を付けさせれば、事実は正しい | 間違い | 461件。照合を通った6件 |
| #06 | 見た目のAIっぽさは、指示で直る | 要検算 | デザインを直したコミット |

| #08 | 上位モデルを使えば解決する | 要検算 | 能力の地図（作る力と確かめる力の差は、上位モデルでも残る） |

## 6. 無料部分の書き出し（型の見本）

```
AIエージェントのコツは、もう十分すぎるほど出回っています。
CLAUDE.md に書け。いや、短くしろ。AIにレビューさせろ。いや、自己評価は甘い。
どれを信じればいいのか。

私はこの5か月、AIエージェントと1,354回コミットして、16の作品を公開しました。
そのうち284回は「直した」記録です。
音楽の地図が黙って消えていた。引用元にない「事実」が461件あった。
どれも、エラーは一度も出ていません。

この連載では、よく言われている通説を1回に1つずつ、この記録で検算します。
効いたもの、半分しか効かなかったもの、逆効果だったもの。
そして、代わりに何をすればいいかを、そのまま使える形で置きます。
```

## 7. 正直に書いておくこと

- 記録は一人のもの。比較実験ではない。判定には「私の記録では」を必ず付ける
- 作ったものは Web の作品（ゲーム、3D、音、地図）に偏っている。業務の資料作りにそのまま当てはまるとは限らない。能力の地図と外部の調査で補う
- 分類は手作業で、境界は主観。件数と一緒に「不明」の数も出す
