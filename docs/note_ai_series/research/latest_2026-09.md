## Claude Code の公式の推奨（best-practices）

https://code.claude.com/docs/en/best-practices.md

- 進め方は「調べる → 計画 → 実装 → コミット」。調べる段階と計画は plan mode（Shift+Tab）でやる。1文で説明できる小さな変更なら、計画は省いてよい。
- **確かめる手段を渡す**（テスト、ビルド、スクリーンショットとの比較）。渡さないと、人間が確認役になってしまう。
- 具体的に頼む。既存のパターンを指し示す。
- コンテキストを積極的に管理する。関係のない作業のあいだは /clear する。同じことを2回直しても直らなければ /clear して、頼み方を変えてやり直す。/compact と /context も使う。
- 早めに軌道修正する。Esc で止める。Esc を2回押すか /rewind で巻き戻す（チェックポイントは Bash による変更を追えない。git の代わりにはならない）。
- CLAUDE.md は短く書く。書くのは、推測できないコマンド、既定と違う規約、注意点。強調を多用すると効かなくなる。毎回必ず実行させたいことは hooks に書く。
- 権限の段階：auto／確認あり（manual）／plan／編集だけ自動（accept edits）。許可リストは settings.json に書く。
- サブエージェントで調べものを別のコンテキストに分ける。Skills は必要なときだけ読み込まれる。
- 注意点：長いセッションでは性能が落ちる。サンドボックスは完全な隔離ではない。MCP サーバーはあなたの権限で動く。Web の中身から指示を紛れ込ませる攻撃（プロンプトインジェクション）がある。
