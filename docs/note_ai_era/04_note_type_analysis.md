## 3. 前のタイトルの診断

> 文面を読まずに「投稿して」と打った。誤りは公開前に6件止まっていた ― AIの出力を「全部目で確認」するのをやめる方法

| 決まり | 判定 | 理由 |
|---|---|---|
| 冒頭25字にキーワード | ✗ | 先頭は「文面を読まずに」。検索されるツール名も悩みの語も無い |
| 何も知らない人が見て分かるか | ✗ | 「投稿して」が何のことか、文脈を知らないと分からない |
| 誰に | ✗ | 読者の指定もツール名も無い |
| 変化の物語の順 | △ | After（今の私）から入っていて、読者の悩みが後に回っている |
| 自分の研究ノート A-10（Xの測り方） | ✗ | 「自分の作品や制作の話は伸びない。読者も同じ目に遭っている体験が伸びる」と自分で書いていたのに、自分の出来事から入っていた |

ニッチに見えた原因は、題材ではなく**入口**だった。中身は同じまま、入口を読者の悩みとツール名に替える。

## 4. 新しいタイトルの設計

型: 人気の証拠がある実例「Claude Codeの承認疲れを減らす｜安全を捨てずに止まらない設定にする」と同じ形。

**［ツール名］の［読者の悩み］を［減らす］｜［条件つきの結果］**

| 案 | 先頭25字 | 誰に | 価値 | 内容 | 判定 |
|---|---|---|---|---|---|
| **Claude Codeの「確認疲れ」を減らす｜全部目で見なくても、ミスは公開前に止まる** | Claude Codeの「確認疲れ」を減らす｜全部 | Claude Code 利用者 | 確認疲れが減る | 目視しなくても止まる仕組み | **採用** |
| AIに任せたのに確認で疲れる人へ｜Claude Codeのミスを目視せず止める仕組み | AIに任せたのに確認で疲れる人へ｜Claud | 明示 | ○ | ○ | 次点（ツール名が25字を超える） |
| Claude Codeの「完了しました」を信じる前に｜確認を目視からコマンドに移す | ○ | ○ | △ 得られるものが弱い | ○ | 不採用 |

- 「なくす」ではなく「減らす」にした。誇大な表現を避けるため（noteヘルプ）。
- 数字と【】は入れない。人気の証拠がある側では少数派だったため。

## 5. 冒頭（無料エリア）の設計

無料エリアの3要素（A 共感 → B 変化の物語 → C ベネフィット）の順に並べ替える。

1. **リード（約50字）**：誰の、何を、どう変えるかを最初に言う
2. **A 共感・問いかけ**：任せたのに、確認で夜が終わる
3. **B 変化の物語**
   - Before：161本の声が数週間消えていた
   - After：文面を読まずに「投稿して」と打っても、6件が公開前に止まった
   - これまで冒頭に置いていた出来事は、ここで「変化の証拠」として使う
4. 原因：作る力は4、確かめる力は2
5. 放置した場合の損失（短く）
6. **C ベネフィット**：読むとできるようになること3つと、渡すもの
7. 地図 → 小さな価値（3つの型の名前）→ 有料の予告
