# プロットだけ用意すれば、Claude Codeが小説にしてゲームにしてくれる

> note投稿用ドラフト / タイトル案は末尾

---

フルボイスのサウンドノベルを個人で作りました。

**[▶ 正解の外側 CASE 01（無料・インストール不要）](https://yuichi916.github.io/seikai.html)**

全15話、13.9万字、ボイス1,593本、背景は3Dの360°パノラマ。ブラウザを開くだけで遊べます。

この記事で書きたいのは、技術の自慢ではなくて、**「人間は何を用意して、AIに何を渡したのか」**です。

結論から言うと、**人間が決めたのは5行だけ**でした。あとは Claude Code が小説に起こし、ゲームに変換し、絵と声と音楽を揃えて、公開までやっています。

その流れがイメージできるように書きます。

②〜③のあいだで一度読み返して直す、という往復はあります。でも**工程そのものは全部渡せます**。

## あなたが決める5スロット

ジャンルを問いません。**この5つが埋まれば書き出せます。**逆にどれかが空だと、その空欄に対応した壊れ方をします。

| # | スロット | 問い | 空欄だと起きること |
|---|---|---|---|
| 1 | **読後感** | 読み終えた人の胸に何が残ってほしい？ | 話は進むが、何のための話か分からなくなる |
| 2 | **主人公の芯** | 何を持っていて、**そのせいで**何を失う？ | 都合よく動く駒になり、感情移入されない |
| 3 | **世界の圧力** | この世界が主人公に強いていることは？ | 障害が場当たりになり、世界が書き割りになる |
| 4 | **中心の関係** | 誰との関係が物語を動かす？その**非対称**は？ | 出来事は起きるが、関係が変化しない |
| 5 | **着地と規模** | どこで終わる？全何話？ | 終われない。永遠に続く |

**全部一行で書きます。**長く書けたら、それは設定資料であって決定ではありません。

### 同じ5スロットが、まったく違う物語を出す

**日常・青春**
```
読後感    : 平凡な日々が、二度と戻らないものだったと気づかせたい
主人公の芯: 何にでも合わせられる / だから自分の欲しいものが分からない
世界の圧力: 期限 — 部活は今年の夏で終わる
中心の関係: 欲しいものをはっきり言う後輩。眩しくて、正視できない
着地と規模: 全12話。最後の大会が終わる日
```

**ミステリ**
```
読後感    : 犯人を憎めなくさせたい
主人公の芯: 細部を見逃さない / だから人の悪意まで見えてしまう
世界の圧力: 掟 — この島では、過去の事故に触れないことになっている
中心の関係: 唯一、彼に嘘をつく依頼人。信じたいのに検証してしまう
着地と規模: 全10話。最後の一人が自白する
```

**今回の作品（SF）**
```
読後感    : 失ったものは戻らないが、それでも進める、と思わせたい
主人公の芯: 最善の道筋が視える / だから失う瞬間も先に視えてしまう
世界の圧力: 禁止 — 悲しむことが制度的に禁じられている
中心の関係: 彼女にだけ道筋が効かない。彼女の前でだけ未来が分からない
着地と規模: 全15話。閉じた場所から出て、空を見る
```

余裕があれば、**絶対に書きたい場面を2〜3個**足すと強くなります。物語をそこへ向けて逆算できるからです。

### コツ①「主人公の芯」は強みと代償を同じ行に

これが物語を自動で生む最小単位です。強みは能力でなくて構いません（立場・性格・過去・技能、何でも）。

```
◯ 何にでも合わせられる / だから自分の欲しいものが分からない
◯ 誰よりも早く走れる   / だから置いていく側にしかなれない
× 優しくて努力家       ← 代償が無い。ただの良い人で、物語が起きない
```

### コツ②「世界の圧力」は禁止だけじゃない

| 類型 | 形 | 例 |
|---|---|---|
| **禁止** | ◯◯してはいけない | 悲しむことが制度的に禁じられている |
| **欠乏** | ◯◯が足りない | 水が配給制で、家族の数で量が決まる |
| **期限** | ◯◯までしかない | 部活は今年の夏で終わる |
| **掟** | ◯◯ということになっている | この島では、過去の事故に触れない |

どれか1つで足ります。そして**世界観はここから派生させます**。設定を広く作り込もうとすると、いつまでも書き始められません。

```
圧力を1つ置く
 → 仕組み : それを維持しているのは何か
 → 例外者 : そこから外れている者は誰か   ← 主人公の居場所になる
 → 抜け道 : 破られている場所はどこか     ← 物語が動く場所
 → 執行者 : 信じて守らせている者は誰か   ← 敵役。悪人である必要はない
```

「期限 — 部活は今年の夏で終わる」に当てると、こうなります。

```
仕組み : 学校制度と大会日程
例外者 : 引退後も来てしまう三年   ← 主人公の居場所
抜け道 : 誰もいない朝の体育館     ← 関係が動く場所
執行者 : 進路を心配する顧問       ← 敵役だが、正しいことを言っている
```

**世界・主人公の立ち位置・舞台・敵が同時に決まりました。**しかも矛盾しません。

### コツ③「中心の関係」は対等にしない

対等な二人は物語になりません。どちらかが、相手の持っていないものを持つ。恋愛でなくて構いません（相棒・師弟・敵・親子でも同じです）。

要は、**主人公の強みが通用しない唯一の相手**を置くと、それだけで関係が物語になります。

## 5行の次にやること — 設定資料集を育てる

5行は**決定**です。ここから、そこに乗る**合意事項**を作ります。世界観、ストーリーの指針、キャラ設定。いわゆる設定資料集です。

**自分で書いてもいいし、AIと壁打ちして固めてもいい**です。決定権さえ手放さなければ、どちらでも同じところに着きます。

これを作らないと、後半で必ず矛盾します。AIが執筆中に参照する唯一の正典になるからです。

### 目次は固定する（これ以上増やさない）

| 章 | 中身 |
|---|---|
| 1 世界 | 圧力とその仕組み / 地理と階層 / 時代と技術水準 / 禁忌と例外 |
| 2 用語 | 固有名詞の一覧と表記の統一 |
| 3 人物 | 主要3人 + 脇役。1人1枚 |
| 4 物語の指針 | 人称・時制・文体 / **やらないこと** |
| 5 話数構成 | 各話の役割を1行ずつ |
| 6 年表 | **作中で言及される過去の出来事だけ** |

**分量の上限は「本編に出ない設定は書かない」。**書きたくなったら、断章や作中の書物として本編に出す形にします。出せないなら、それは要らない設定です。

ここを決めておかないと、設定を作ること自体が楽しくなって、いつまでも書き始められません。

### 用語表がいちばん事故を防ぐ

意外かもしれませんが、AI執筆で最も頻発する破綻は世界観ではなく**表記ゆれ**です。

「アビス／深淵」「五一七／517」「監督官／管理官」が混在すると、検索も改稿も効かなくなります。正式表記・読み・初出話をただの表にしておくだけで、これが消えます。

### キャラシートは1人1枚

```
一行紹介   : 試験に14回落ち続けている男
話し方の癖 : 語尾を飲み込む
身体の癖   : 無意識に右手で空をなぞる     ← 感情を説明せず、身体に宿す
隠した一面 : 誰も見ていない所で配給を差し入れている
呼び方     : 主人公→「あんた」 / ヒロイン→「お嬢ちゃん」
```

- **身体化した癖**を1つ入れておくと強いです。全編で反復して、誰かがそれを見抜く瞬間が山場になります
- **呼び方の表**は地味ですが効きます。同じ人物でも呼ぶ相手で温度が変わって、人間関係が立体になります

### 「やらないこと」を書く

指針は「やること」より**「やらないこと」**のほうが効きます。そのままAIへの制約になるからです。

```
やらない: 説明台詞で世界設定を語らせない
やらない: 主人公に自分の感情を言語化させない（身体と行動で出す）
やらない: 章末を疑問形で終わらせない
```

### 壁打ちの型

AIと固めるときは、頼み方で結果がまるで変わります。

| 目的 | 頼み方 | 注意 |
|---|---|---|
| **選択肢を出させる** | 「◯◯の案を5つ、方向性を変えて」 | **選ぶのは自分**。採用理由を一行残す |
| **矛盾を突かせる** | 「この設定で破綻する場面を挙げて」 | いちばん費用対効果が高い |
| **尋問させる** | 「作者に質問して。答えないと書けない順に」 | 自分の空欄が可視化されます |
| **平凡さを検出させる** | 「この設定でありがちな展開を10個」 | 出たものを**避ける**ために使う |

**やってはいけないのは「いい感じにして」「膨らませて」**です。整合はするけれど、誰の作品でもないものが出てきます。

壁打ちは選択肢を増やす道具であって、決定を代行させる道具ではありません。ここを間違えると、5行を決めた意味が消えます。

### 止め時

次の3つが埋まったら終わりにします。**それ以上は本文を書きながら足す。**

1. 用語表が埋まっている
2. 主要3人の呼び方の表が埋まっている
3. 各話の役割が1行ずつ書けている

### 資料集は生き物

執筆中に決まった事実（誰の目が何色か、あの部屋に窓はあるか）は、**その場で資料集に書き戻します**。

そして矛盾を見つけたら、**資料集を上位として本文を直す**。逆をやると際限がなくなります。

## Claude Codeに任せたこと

- **各話の配分と配置表** — 何話目でどの伏線が現れるか
- **脇役の設計・名前・見せ場**、地名・組織名・専門用語
- **地の文と会話の執筆**、文体の統一
- **伏線の敷設と回収の管理**
- 台本への変換、エンジンの実装、画像・音声の生成、検証、公開

任せてよかった理由はシンプルで、**5スロットが埋まっていれば、残りは整合性の問題だから**です。

逆に言うと、5スロットが曖昧なまま丸投げすると、**整合はしているのに心に残らないもの**が出てきます。ここが分かれ目でした。

## 実際の流れ

### 小説になるまで

配置表を先に作らせます。「第N話でフックがどう現れるか」を全話ぶん表にしてもらう。

**表の段階なら、破綻は1行直せば消えます。**本文を書いてから気づくと、1話まるごと消すことになります。ここを飛ばすと後で高くつきました。

表にOKを出したら、あとは1話ずつ書いてもらいます。**1話 = 1ファイル**（`ep01.md` …）にしておくと、あとで直すときに影響範囲が目で追えます。

そして**完結させてから推敲**します。未完のまま推敲に入ると永遠に終わりません。

### ゲームになるまで

ここが一番「へえ」と思ったところです。

小説の地の文と会話は構造が決まっているので、**ゲームの台本への一次変換はスクリプトで機械的にできます**。

```js
window.SEIKAI_SCRIPT = { ep1: { scenes:[
  { bg:'slumA', bgm:'under', beats:[
    {say:'della', text:'「目つきが気に入らねえ」'},
    {say:'kai',   text:'「了解」', ex:''},
    {show:'kai', pos:'right'},
    {say:'potz',  text:'「毎朝毎朝、よく耐えるな」'},
    {say:'narr',  text:'隣の奴隷——五一八番のポッツが小声で言った。'},
  ]},
]}};
```

![小説がそのままゲームになる](C:\projects\yuichi916.github.io\assets\seikai\publish\making\05_novel_to_game.png)
*同じ場面が、小説 → 台本データ → ゲーム画面と変わっていく*

`「…」` を台詞ビートに、場面転換を背景切替に、心内描写を内心フラグ付きの台詞に落とす。**台本はただのデータで、エンジンはそれを再生するだけ**にしておくと、エンジンに触らずに物語を増やせます。

小説が完結していたので、**着手から4時間半で全15話がブラウザで動きました。**

![タイトル画面の進化](C:\projects\yuichi916.github.io\assets\seikai\publish\making\02_title_evolution.png)

ここから先の1ヶ月半で、背景・ボイス・ミニマップ・断章・OPが乗っていきます。**動くところまでは速い。作品になるまでが本番**というのは、この2枚の差のことです。


順番が全部でした。台本を書きながらエンジンを作ると、物語の不確定性とコードの不確定性を同時に抱えることになって、どちらも収束しません。

### 声

ElevenLabs で、**主役2人だけ**フルボイスにしました。

これは予算の話ではなく**容量の話**です。全キャラに声を付けると500MB超えて、置ける場所がなくなります。主役2人なら200MB程度に収まる。しかも、2人だけが喋ると「**この2人の物語なんだ**」と伝わって、演出としてむしろ良かったです。

生成は数時間かかるので、寝る前に回しておく感じでした。

### 音楽

- **主題歌は Suno**。OPの尺（90秒前後）に合わせて作ります
- **BGMは配布素材**。自作より圧倒的に速くて、質も安定します

BGMは10〜17曲で足ります。「地下 / 緊張 / 会話 / 悲哀 / 地上 / 静寂」みたいなカテゴリを埋めて、シーンごとに割り当てるだけ。

**主題歌があるとOPが成立して、作品の格が一段変わります。**ここは削らないほうがいいです。

### OP映像

**[▶ OP（92秒）](https://www.youtube.com/watch?v=AYpOA6ArBCg)**

動画編集ソフトは使っていません。**HTMLを時間駆動にして、1フレームずつ書き出しています。**

```js
window.__setTime = (t) => { /* 任意時刻の画面を完全再現 */ };
```

あとは Playwright で `__setTime(t)` を呼んでスクリーンショット、92秒×30fpsで2,760枚、ffmpeg で結合。

全部を「時刻 t の関数」として書くのがポイントで、CSSのアニメーションに任せると書き出しでズレます。

## 公開は git push だけ

ここも意外と大事なので書いておきます。

**GitHub Pages に静的HTMLを置いているだけです。ビルド工程がありません。**

```
リポジトリ直下
  seikai.html          ← ルートに置いたHTMLがそのままURLになる
  assets/seikai/       ← 画像・音声・台本
  .nojekyll            ← 空ファイル。これ1個だけ必須
```

- `package.json` も設定ファイルも要りません
- ライブラリ（three.js など）はCDNから読みます
- `.nojekyll` という空ファイルを1個置く。これが無いと Jekyll のビルドが挟まって面倒になります
- 公開は `git push` のみ。数十秒で反映されます

**バンドラを入れた瞬間に「デプロイ＝ビルド＋確認」になって、反復速度が落ちます。**個人で作品を作るなら、ビルドを持たないのが一番速い。

Node.js は使いますが、**ビルドではなく検査用**です。単一の大きなHTMLは壊れても画面が出ないだけなので、`node --check` で構文を通してからコミットします。

## どこまで自分でやるべきか

やってみた実感として、線はここでした。

**自分でやる**
- 5スロットを埋める
- 設定資料集の決定に責任を持つ（壁打ちの相手はAIでいい）
- 配置表にOKを出す
- 書き上がった小説を**読む**（ここは代替できません）
- 「絶対に書きたい場面」が書けているか確認する

**渡していい**
- それ以外の全部

小説を読み返す作業だけは残ります。というより、**そこが唯一の楽しみ**でもありました。自分が決めた5行から、読んだことのない物語が出てくるので。

## 時間が足りないとき、どこを削るか

上から順に削れます。下は削ってはいけません。

1. ミニゲーム・探索・コレクション
2. Blenderパノラマ → SD背景に落とす
3. OP映像
4. 脇役の立ち絵
5. 表情差分（1キャラ1枚でも成立します）

削ってはいけないもの:

- **主役2人のボイス** — 削ると凡百のノベルゲームになります
- **小説の完結** — 未完は作品ではありません
- **セーブ / スキップ / 章選択** — 無いと3時間の作品は遊ばれません
