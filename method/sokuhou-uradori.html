03

根拠台帳：数字は原文の文字列で裏付ける

新しいモデルの話なので、エージェント自身の知識はあてになりません（学習の時点より後の発表です）。 そこで、使う事実を全部台帳に登録し、台帳に無い数字は画面にも本文にも書かない、という決まりにしました。 

{
  "id": "L01",
  "ja": "大半の作業で Fable 5.1 並みの性能。Opus 5 より約4割安く動く",
  "values": ["40%", "4割"],
  "quote": "It performs at the level of Claude Fable 5.1 on most work and costs 40% less to run than Opus 5.",
  "source": "announce.txt",
  "reading": "on most work = 大半の作業で。全作業ではない。"
}

台帳を検査するスクリプトは、2つのことだけをします。

  1. 引用の照合：各 quote が、保存した原文にそのまま存在するか（空白と引用符の揺れだけ吸収）。
  2. 数値の照合：動画のHTML・投稿文・説明文に出てくる数字を全部抜き出し、台帳の values にあるか。モデル名の版数（5.5 など）は先に落とす。
26/26引用が原文に存在
41 · 4 · 25X動画・投稿文・YouTube説明文の数字
すべて台帳内
5/6わざと混ぜた誤りを
検出できた数

照合器が何を見逃すかを、先に測る

検査が通っても、検査そのものが甘ければ意味がありません。そこで、誤った文を6つ作って照合器に通しました。

混ぜた誤り正しくは結果
Opus 5.5 は 66.5%66.4%検出
Opus 5 より5割安い4割検出
18本中17本 合格16本検出
$0.25$0.20検出
6時間枠5時間枠検出
出力が40%速い30%以上見逃し

最後の1つは、「40%」が台帳に（費用の値として）存在するので素通りします。 数値の照合は「その値がどこかにあるか」しか見ていないので、正しい値を別の文脈で使うと捕まりません。 これは照合器を直せば済む話ではなく、文を読む担当が別に要る、ということです（07）。

04

X用の動画の作り方

Xの動画は最初ミュートで自動再生されるので、音がなくても全部伝わる形にしました。 画面は1枚のHTMLで、全部のアニメーションを時刻 t の関数として書きます。 こうすると、Playwrightで1/30秒ずつ時刻を進めて撮るだけで、何度書き出しても同じ絵になります。 

function setTime(t) {
  // 背景の模様・ぼかしの光は、どの時刻でも少しずつ動く（静止判定の対策）
  $('grid').style.transform = `translate(${(t * 16) % 80}px, ${(t * 9) % 80}px)`;
  for (const sc of SCENES) {                 // 8場面。data-s〜data-e の間だけ表示
    const on = t >= sc.s && t < sc.e;
    sc.el.style.visibility = on ? 'visible' : 'hidden';
    if (on) for (const it of sc.items) animItem(it, t - sc.s);  // 出現・棒・数え上げ
  }
}
window.__setTime = setTime;   // 撮影側は evaluate("t => __setTime(t)") → screenshot

X用動画の時間割。場面の切れ目・和音の変わり目・ドラムの入りを全部、120BPMの拍（0.5秒刻み）にそろえた。効果音は画面の要素が出る時刻と同じ式から計算している。

BGMは、耳ではなくスペクトルで確かめる

エージェントは音を聴けません。そこで帯域ごとのエネルギーを測りました。 1回目の合成は16kHz帯が強く、スマホのスピーカーでシャリシャリ聞こえる形でした。 ハイハットを7.5〜12kHzに絞って音量を下げ、16kHz帯を −22.1dB → −28.3dB にしています（最大の帯を0dBとした相対値）。

5〜28秒のオクターブ帯エネルギー（最大の帯を0dB）。低音の山（63Hz）はそのまま、上の2帯だけを下げた。最終のミックスは -14.1 LUFS／ピーク -2.8 dBFS。

既存の手順にあった落とし穴

  • 台本の生成スクリプトが、全話の台本を書き直す。過去回の場面時刻まで空に戻るので、実行の前後で過去回を退避・復元した。
  • 字幕を直しても、画面に反映されない。字幕は合成時にタイミングのファイルへ写されるので、合成の手順をやり直す必要がある（声はキャッシュされるので数秒で終わる）。
  • 投稿スクリプトがジャンルを名前で読む。説明文データのジャンルは番号で持っていたので、そのままだと「旅行」で公開されるところだった。投稿用のデータに名前で入れ、公開後にAPIで「科学と技術（28）」を確認した。
  • 座標の検査は1字だけの改行を拾わない。見出し「…(米国時間)発表」の「表」だけが3行目に落ちていた。書き出したフレームを見て見つけた。

品質チェックの全体像（4層）

検査は4層に分かれています。下の層ほど機械的で速く、上の層ほど意味を読みます。 どの層も、何かを確実に捕まえ、何かを確実に素通りさせます。素通りの側を知っておくことが、層を重ねる理由です。

L4
別エージェントの審査9回・観点ごとに別の担当
捕まえる条件の違う数字の接続、内訳の脱落、書いていない含意、1行目の弱さ、スマホでの読めなさ
素通り・弱点採点が担当ごとにぶれる。点数は直しても上がり続けない。書き出し前の古いファイルを見ることがある
L3
媒体の機械検査音・絵・座標・読み
捕まえる音圧・音割れ・無音、黒フレーム、静止、安全域、要素の重なり、出典の帯への食い込み、誤読
素通り文の意味。1字だけの改行や、単語の途中の改行（座標は正しいので）
L2
数値の照合画面・本文の数字 ⊂ 台帳の値
捕まえる台帳にない数字（記憶で書いた数字、打ち間違い）
素通り正しい値を別の文脈で使うこと（「出力が40%速い」）
L1
引用の照合台帳の一文 ⊂ 保存した原文
捕まえる存在しない引用（捏造した根拠）
素通り本物の一文を読み違えること

10

自分の題材でやるなら

  1. 題名と1行目は、全体像から入る。「何が出て、全体としてどう良くなったか」を先に言い、個別の検証や意外な数字は後ろに回す。細部から入った最初の投稿は読まれず、書き直して再投稿した。
  2. 一次情報をファイルに保存してから書く。記憶や検索結果の要約から書かない。新しい発表ほど、エージェントの知識は古い。
  3. 使う事実を台帳にする。「日本語の主張・値・原文の一文・読み方の注意」を1件ずつ。原文に文字列が無いものは登録できない形にする。
  4. 画面と本文の数字を、台帳と機械で照合する。台帳外の数字が1つでもあれば止める。
  5. 照合器に誤りを混ぜて、何を見逃すかを先に知る。今回は6つ中1つを見逃した。見逃す種類が、次の層の仕事になる。
  6. 事実の担当を別に立て、3つの型を渡す。条件の違う数字の接続・内訳の脱落・書いていない含意。「引用が本物か」ではなく「引用が主張を支えているか」を読ませる。
  7. 媒体の検査は機械で先に潰す。音圧・無音・黒・静止・安全域・重なり・余白・誤読。担当には、機械で測れないものだけを見せる。
  8. 書き出したフレームは自分でも見る。1字だけの改行や単語の途中の改行は、座標の検査を通る。
  9. 点数では止めず、事実の必須項目で止める。点数は担当ごとにぶれる。事実の中程度以上が0件になるまでは出さない。
  10. 公開後は、公開ページの側で確かめる。投稿先の名前、リンクの転送先、ジャンルと公開状態。スクリプトの「完了」表示は証拠にならない。

def norm(s):
    s = s.replace("’", "'").replace("“", '"').replace("”", '"')
    return re.sub(r"\s+", " ", s).strip()

def quote_found(quote, source_text):          # L1: 引用が原文にあるか
    return norm(quote) in norm(source_text)

NUM = re.compile(r"\$?(?:\d{1,3}(?:,\d{3})+|\d+)(?:\.\d+)?(?:%|割|時間|本|万)?")
def numbers_in(text):                          # L2: 画面・本文の数字を全部抜く
    for p in NAME_PATTERNS:                    # 「Opus 5.5」などの版数は先に落とす
        text = re.sub(p, " ", text)
    return [m.group(0) for m in NUM.finditer(text)]
